## 提示词正文

你要把一个手写的落地页（HTML + CSS + JS，带滚动动效和交互）放到 Wix 站点的某个页面上。我们是做海外众筹预热页的团队，页面的唯一目的是收集邮箱，所以有一条硬性要求贯穿始终：

**邮箱必须由 Wix 原生表单收集。** 访客在页面上的输入框里填一次邮箱、点提交，数据直接进 Wix 后台，随后弹出 Wix 自己的弹窗（引导进群或付定金）。你写的代码不能经手邮箱：不能自己做输入框再转存，不能调接口代写。原因是运营同事只在 Wix 后台看数据、挂自动邮件，任何绕开原生表单的做法一旦丢数据没人能发现。

同时页面的动效和交互要完整保留，页面结构要和我们以往的范例一致：首屏、中段、结尾各有一个邮箱框，直接显示在页面上，不是常驻底栏，也不是点按钮才弹出。

### 为什么用「自定义元素」

Wix 里放自定义代码有两种方式，区别决定了成败：

- **嵌入网页（HTML iframe）**：页面上开一个小窗口装另一张网页。窗口里的代码感知不到 Wix 页面的滚动，跟随滚动的动效全部失效；原生表单也没法嵌进窗口里。不要用。
- **自定义元素（Custom Element）**：你的代码直接运行在 Wix 页面本身里，和页面共用同一个滚动。原生表单可以和它放在同一个区块里叠在上面。用这个。

前提：按 Wix 的规则，自定义元素要求站点是付费套餐并绑定了自己的域名。这一条我们只在付费站点上验证过，免费的 wixsite.com 站点没有实测。开工前先确认站点满足条件；不确定就先放一个最小的测试元素发布验证，再做正事。

### 整体结构

1. 把落地页打包成**一个脚本文件**，里面注册一个自定义元素标签。脚本负责注入样式、渲染 HTML、启动动效。
2. 脚本存进站点自己的代码文件（`public/custom-elements/<名字>.js`），图片上传到站点的媒体库。不使用任何外部托管，这样所有东西都在客户的 Wix 账号里。
3. Wix 页面按「需要表单的位置」切成几个区块。每个区块放一个自定义元素，用属性区分显示页面的哪一段；需要表单的区块里再放一个原生 Wix 表单，叠在自定义元素上面。
4. 你的页面在每个该出现邮箱框的地方留一个空的占位元素。脚本在运行时量出占位的位置，把同区块里的 Wix 表单用 `transform` 挪过去，窗口尺寸变化和字体加载后重新对齐。这样版式可以自由设计，不受 Wix 编辑器坐标的限制，电脑和手机通用。

### 打包时必须处理的事

- **样式隔离**：你的 CSS 会和 Wix 的全局样式互相影响。给所有选择器加一个统一的根类前缀，把原来写在 `html` / `body` / `:root` 上的规则改挂到根类上；`@keyframes` 名字加前缀。
- **宽度**：Wix 有一条样式会把自定义元素的宽度压回编辑器里的 980px。根元素的宽度要用带 `!important` 的规则设成视口宽度，并用负的左边距铺满全屏。
- **高度**：不用管。Wix 的区块高度会跟着自定义元素的内容自动撑开，编辑器里给个小的最小高度即可。
- **第三方库内联**：动效库直接打进脚本，不要运行时再从 CDN 加载，少两次请求，也避免目标网络访问不了。
- **去掉不适用的东西**：平滑滚动库（会和 Wix 页面的滚动冲突）、自己写的表单和提交逻辑、依赖独立页面顶栏的逻辑。
- **固定定位的图层**（全屏光晕、噪点等）：会溢出到别的区块。给根元素加 `clip-path: inset(0)` 把它们裁在自己的区块内。需要跨区块的东西（比如自定义光标）挂到 `body` 下单独的容器里。

### Wix 环境里会失效的写法

这些是实际踩过的坑，直接避开：

- **判断"元素是否在屏幕里"一律用 `IntersectionObserver`。** 不要用滚动库按位置计算的触发器来做这件事：Wix 页面的 `load` 事件在你的脚本运行之前就已经触发过了，字体和图片后到，算出的位置会过期，表现是"轮播不自动切换""数字不跳动"。滚动库只用于真正跟随滚动的动画，并且用 `ResizeObserver` 监听根元素，尺寸变化后刷新它的位置。
- **Wix 会等自己的页面加载完才请求你的脚本**，发布后的第一次访问还要现场打包，更慢。所以首屏不能依赖脚本：给首屏区块设一张 Wix 原生的背景图（首屏的静帧）先顶着，脚本和主图就绪后再隐藏它。首屏的文字不要做"先隐藏再入场"的动画。
- **编辑器的「预览」不能用来验证。** 预览里自定义元素被关在隔离框里，是空白的。只有发布后的线上页面才是真实效果。
- **手机版是另一套布局。** Wix 手机版按 320 宽单独排版，新加的组件默认可能被隐藏。需要：把页面的手机版也设为落地页（去页眉页脚）、把表单在手机布局里显示出来、把自定义元素设成贴边满宽。**手机布局里表单的位置必须和自定义元素重叠**，否则 Wix 会把表单排到元素下方，留出一条空白。
- **图片**要有全局的 `height: auto`，否则带宽高属性的图片在限宽时会被压扁。

### 操作 Wix 的方式

浏览器操作一律用 `ego-browser`（复用已登录的 Wix 账号）。Wix 经典编辑器可以不点界面、直接调内部接口：

- 入口：编辑器页面里 `document.getElementById("preview").contentWindow.documentServices`（下面简称 `ds`）。
- 改动后等待生效：`await new Promise(r => ds.waitForChangesApplied(r))`；用 `ds.registerToErrorThrown` 才能看到真实报错。
- 写代码文件：`ds.wixCode.fileSystem.writeFile(ds.wixCode.fileSystem.getVirtualDescriptor("public/custom-elements/x.js", false), code)`，然后 `flush()`。
- 加自定义元素：`ds.components.buildDefaultComponentStructure("wixui.CustomElementComponent")`，把 `data.tagName` 设为你的标签名、`data.url` 设为代码文件路径、`data.hostedInCorvid` 设为 `true`、`data.initialAttributes` 设为属性的 JSON 字符串，再 `ds.components.add(区块引用, 结构)`。
- 上传图片：用 `ds.wixCode.getClientSpec().instance` 作为 `Authorization`，调 `https://www.wixapis.com/site-media/v1/files/generate-upload-url` 拿到上传地址，再 `PUT` 文件内容，返回里有图片的正式地址。这个令牌只在内存里用，不要写进文件或打印出来。
- 页面设置：`ds.pages.data.update(页面id, { isLandingPage: true, isMobileLandingPage: true })`。
- 手机布局：组件引用的 `type` 用 `"MOBILE"`；显示被隐藏的组件用 `ds.mobile.hiddenComponents.show(组件id, 页面id)`。
- 发布：点编辑器右上角的发布按钮，等成功提示。

把「上传新图片 → 写入脚本 → 发布」写成一个可重复执行的部署脚本，并维护一份「本地图片路径 → Wix 图片地址」的映射文件，打包时按映射替换图片地址。

### 关于表单本身

- **表单要用 Wix 的界面新建**，或者由运营同事建好给你。不要用接口把别的页面的表单复制过来当正式表单：复制出来的表单仍然指向原来那一个，数据会混进原表单的提交记录，提交后弹的也是原表单的弹窗。复制只适合临时验证位置和样式。
- 你可以调整表单的外观（颜色、圆角、字号、输入框和按钮的尺寸）让它和页面融合，可以删掉表单里多余的文字和图片，只留输入框和按钮。不要改表单的数据设置。
- **不要自己提交表单做测试。** 提交会往真实后台写入数据并触发自动邮件。需要测试时先问我，由我指定测试邮箱或让运营来测。

### 安全边界

- Wix 的发布是**整站发布**，会把站内其他页面未发布的草稿一起推上线。每次发布前确认：这个站点上有没有别人正在编辑、其他页面有没有不能上线的草稿。第一次发布前必须问我。
- 只动我指定的那一个页面。站内其他页面、站点设置、其他表单一律不碰。
- 遇到需要改站点级设置（自定义代码、域名、套餐、应用安装）才能继续的情况，停下来问我。

### 交付时告诉我

- 线上地址，以及你在哪些窗口宽度和手机尺寸下看过。
- 三处表单的位置是否对齐（给出实测偏差）。
- 哪些是你实际验证过的，哪些没有（尤其是表单提交、弹窗、真机表现）。
- 这次一共发布了几次，有没有动到指定页面以外的东西。

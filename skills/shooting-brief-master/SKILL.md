# Shooting Brief Master

众筹产品拍摄需求文档生成器。  
输入产品信息 → 输出一份可直接发给品牌方/摄影团队的完整 HTML 拍摄需求文档（样式精美，可打印/存 PDF）。

---

## 工作流程

### Step 1：读取 KSP，自动提炼变量

用户触发后，**先读取用户提供的 KSP**（文字/文件/截图/PDF 均可）。  
从 KSP 中自动提炼以下变量，**不需要逐一问用户**：

| 变量 | 提炼来源 | 处理方式 |
|---|---|---|
| `{{产品名称}}` | KSP 标题/品牌字段 | 直接提取 |
| `{{核心功能列表}}` | KSP 功能/卖点描述 | 提炼为 3～6 条简洁英文导向描述，北美化 |
| `{{产品Slogan_EN}}` | KSP slogan 或主标题 | 若有中文 slogan，翻译并优化为北美受众语感 |
| `{{产品Slogan_CN}}` | KSP 中文 slogan | 直接提取，无则留空 |
| `{{目标场景列表}}` | KSP 使用场景 | 结合产品类型，替换/补充为北美常见户外场景（如：tailgating、RV trip、backyard BBQ、beach day、road trip、camping） |
| `{{目标用户}}` | KSP 目标用户 | 替换为北美受众描述（如：outdoor enthusiasts、weekend warriors、van lifers、families） |
| `{{众筹市场}}` | 用户说明/平台名/KSP 语言与渠道 | 识别为欧美众筹、日本众筹或其他市场，用于场景、模特和 AI 参考图本地化 |
| `{{默认模特人群}}` | `{{众筹市场}}` | 欧美众筹默认欧美白人模特；日本众筹默认日本人模特；其他市场按产品目标市场推断 |
| `{{材质描述}}` | KSP 材质/工艺字段 | 直接提取，补充外观细节 |
| `{{核心部件列表}}` | KSP 部件/技术规格 | 提炼为拍摄需要特写的部件列表 |
| `{{产品规格}}` | KSP 规格表 | 直接提取尺寸/重量/颜色 |
| `{{配件清单}}` | KSP 包装清单 | 直接提取，无则写"[待确认]" |
| `{{视频时长}}` | — | 默认：主视频 90 秒 / 社媒版 30 秒 |
| `{{痛点场景描述}}` | KSP 痛点/使用背景 | 转化为北美生活场景的视觉化开场描述 |

**北美本地化原则（Claude 主动执行）：**
- 场景优先选北美高关联度场景：camping / tailgating / RV / backyard / road trip / beach / off-grid
- 模特建议写为：white Western / North American models by default，可描述为 rugged-looking male model + casual female model（覆盖更广受众）
- 功能描述避免直译，转为 benefit-oriented 语言（如"双模式切换" → "Switch between AC and fridge mode in one tap"）
- 品质测试镜头参考北美消费者关注点：noise level、battery life、durability、weather resistance

**众筹市场与 AI 模特默认规则：**
- 欧美众筹（Kickstarter / Indiegogo / Amazon Launchpad / 北美或欧洲市场）：AI 生图中的人物模特默认使用欧美白人，场景默认北美/欧洲生活方式语境。
- 日本众筹（Makuake / Campfire / Green Funding / 日本市场）：AI 生图中的人物模特默认使用日本人，场景默认日本生活方式语境。
- 若用户明确指定平台、国家、族裔、多元化要求或品牌方限制，以用户指定为准。
- 若画面是纯产品棚拍、材质微距、结构拆解、生产线、渲染六视图，不需要出现人物模特。

**平台识别规则：**
- 用户提到 `KS`、`Kickstarter`、`IGG`、`Indiegogo`、`欧美众筹`、`北美众筹`、`US`、`USA`、`EU`、`Europe`，将 `{{众筹市场}}` 识别为欧美众筹。
- 用户提到 `Makuake`、`マクアケ`、`Campfire`、`CAMPFIRE`、`Green Funding`、`GREEN FUNDING`、`日本众筹`、`日本市场`、`JP`、`Japan`，将 `{{众筹市场}}` 识别为日本众筹。
- 用户同时提到多个平台时，按本次要交付的主要平台判断；若无法判断主平台，在文档中优先使用更中性的产品图，人物场景图按用户最先提到的平台本地化。
- 用户未提平台时，根据 KSP 语言、价格币种、销售渠道、竞品平台和用户已有上下文推断；仍无法判断时默认欧美众筹。

**补问规则：**  
提炼完毕后，如有以下情况才补问，**一次性，不超过 3 个问题**：
1. KSP 完全没有提到 slogan / 主题语
2. 产品有多个 SKU / 颜色，不确定本次主推哪个
3. 有品牌方特定限制（如不能出现竞品 logo、模特需符合特定形象）

格式示例：
```
从 KSP 我提炼到以下信息，有 2 点需要确认：
① Slogan 方向：KSP 没有提供，你倾向于强调便携性还是双功能？
② 本次主推颜色：KSP 提到有 Black / Olive Green 两色，主拍哪个？
```

### Step 3：竞品拍摄风格调研（网络搜索）

变量确认完毕后，**在生成文档之前**，主动用网络搜索了解竞品的拍摄风格。

**搜索策略：**

1. 搜索关键词组合（根据产品类型动态生成）：
   - `{产品品类} Kickstarter campaign video 2024`
   - `{产品品类} crowdfunding product photography`
   - `best {产品品类} outdoor lifestyle photography`
   - 例：`portable AC fridge Kickstarter campaign video`、`camping cooler product photography lifestyle`

2. 重点观察并提炼以下维度：
   - **场景选择**：竞品主打哪些场景？北美哪些场景出现频率最高？
   - **模特风格**：竞品用什么类型的模特？年龄/风格/族裔多样性？
   - **镜头语言**：大特写 vs 生活场景的比例？产品使用方式如何呈现？
   - **视频节奏**：痛点开场方式、功能演示节奏、收尾 slogan 处理
   - **差异化机会**：竞品普遍缺失哪些场景或角度？

3. 将调研结论**直接融入文档内容**（不单独输出调研报告），在受竞品调研影响的条目后加注 `（参考竞品：此构图/场景效果突出）`

**搜索失败处理：** 若无有效结果，跳过此步骤，在文档顶部加注"竞品调研数据不足，场景建议基于品类通用最佳实践"

### Step 4：生成/加载参考图

生成 HTML 前，先处理参考文件列。参考文件列必须使用当前确认版排版：页面 `max-width: 1280px`；有参考文件列的表格列宽 `260px`；`.ref-img` 屏幕版 `height: 170px`、`object-fit: contain`、`padding: 4px`，严禁用 `object-fit: cover` 裁切图片；打印版 `.ref-img` 高度 `125px`。

#### 4.1 产品静态图实拍 + 渲染模块：默认 AI 生图

对「一. 产品静态图实拍 + 渲染」9 个子项的参考文件图片，默认全部使用项目专属 AI 生图，不再使用通用固定参考图作为最终参考图：

1. KV 侧面 45° 或正面
2. 核心功能（静态图）
3. 产品特写（静态图）
4. 材质细节（静态图）
5. 场景应用（静态图）
6. 生活镜头（静态图）
7. 产品品质
8. 纯色背景渲染图
9. 核心部件

**AI 参考图生成规则：**

1. 使用 `imagegen` skill 的内置 `image_gen` 工具生成位图参考图；每个子项 1 张，横图构图，建议 16:9 或 4:3。
2. 提示词必须基于该项目的产品名称、形态、材质、核心功能、目标场景，不要生成与产品无关的泛品类图片。
3. 带人物的 AI 参考图必须遵守 `{{众筹市场}}` 的模特默认规则：欧美众筹默认欧美白人，日本众筹默认日本人；纯产品/材质/结构图不加人物。
4. 参考图只用于表达构图、机位、材质、场景氛围和画面语言；不要生成品牌 logo、平台 logo、水印、价格、UI 文案或不可控大段文字。
5. 每张图生成后复制/压缩到当前项目输出目录，例如 `outputs/assets/{产品slug}-references/`，再转为 base64 data URI 内嵌到最终 HTML，保证交付仍是单个 `.html` 文件。
6. 图注要短，按子项明确区分，避免“产品特写 / 材质细节 / 核心部件”重复：
   - 产品特写：正面 45°、侧面与结构轮廓
   - 材质细节：面料、拉链、接口、透明窗等微距
   - 核心部件：电子模块、主控、电池、声学/传感器等拆解或结构示意
7. 如果 `image_gen` 不可用，才回退到通用固定参考图，并在最终说明里标注“静态模块参考图已回退为通用参考图”。

#### 4.2 视频/生产运输模块：加载全项目通用固定参考图

对于「二. 产品视频拍摄」和「三. 设计生产运输拍摄」中需要参考文件的部分，读取固定参考图配置：

- 映射表：`references/static-reference-map.md`
- 机器可读清单：`references/static-reference-manifest.json`
- 图片目录：`assets/static-references/`

**固定参考图使用原则：**

1. 这些图片是所有项目都可复用的构图/机位/画面语言参考，不需要用户每次单独提供。
2. 参考图只放在 HTML 表格的"参考文件"列，不要混入"要求"文字。
3. 优先按 `references/static-reference-map.md` 的 slot 映射替换模板变量，如 `{{参考图_生产过程}}`；静态模块的 `{{参考图_KV}}` 至 `{{参考图_核心部件}}` 应优先被 AI 参考图替换。
4. 运行 `scripts/build_static_ref_html.py` 生成固定参考图 HTML 片段 JSON，并用结果替换模板中的 `{{参考图_*}}` 变量。
5. 若映射表指定的图片文件存在，将图片转为 base64 data URI 写入 HTML，保证最终交付仍是单个 `.html` 文件、无外部依赖。
6. 若对应图片不存在，保留灰色占位框：`<div class="img-placeholder">参考图<br>[请插入]</div>`。
7. 每个参考文件单元格最多放 1 张主参考图，并配简短图注；不要把参考图做成大图瀑布流，避免破坏 A4 打印布局。
8. 如果用户额外提供了本项目专属参考图，则项目专属图优先；固定参考图作为补充。

**固定参考图维护方式：**

- 新增/替换通用图片时，把文件放入 `assets/static-references/`
- 同步更新 `references/static-reference-manifest.json` 中的文件名和图注；`references/static-reference-map.md` 作为给人看的说明
- 图片建议使用 `.jpg` / `.png` / `.webp`，单张尽量小于 1 MB

### Step 5：生成 HTML 文档

按以下结构生成完整 HTML。**严格按模板结构**，不要省略任何章节，不要自由发挥结构。

参考 `references/html-template.md` 获取完整 HTML 骨架和样式。
参考 `references/static-reference-map.md` 获取固定参考图 slot 映射。
运行 `scripts/build_static_ref_html.py` 获取固定参考图变量替换 JSON。

静态模块 AI 参考图必须覆盖以下 slot：`{{参考图_KV}}`、`{{参考图_核心功能}}`、`{{参考图_产品特写}}`、`{{参考图_材质细节}}`、`{{参考图_场景应用}}`、`{{参考图_生活镜头}}`、`{{参考图_产品品质}}`、`{{参考图_纯色渲染}}`、`{{参考图_核心部件}}`。固定参考图 JSON 只作为这些 slot 缺失时的回退。

输出时先生成 `.html` 文件到 `/mnt/user-data/outputs/`，文件名格式：  
`{产品名称}_拍摄需求.html`

客户交付优先同时生成单页长图式 PDF，文件名格式：  
`{产品名称}_拍摄需求_单页长图版.pdf`

**PDF 导出规则：**

1. 客户交付默认使用“单页长图式 PDF”，不是分页 A4 PDF，避免大面积留白和表格被分页截断。
2. 使用浏览器渲染屏幕版样式导出：`emulateMedia({ media: "screen" })`，读取页面 `scrollHeight` 后把 PDF 高度设为完整内容高度 + 底部余量。
3. PDF 参数必须关闭页眉页脚，边距设为 0，开启 `printBackground: true`。
4. 导出后必须检查 PDF 页数，默认应为 1 页；若不是 1 页，需要重新计算页面高度或降低缩放后再导出。
5. 只有用户明确要求“可打印 A4 分页版”时，才额外生成分页 PDF。

## 文档结构（章节顺序固定）

### 封面区
- 标题：`{产品名称} × 众筹拍摄需求文档`
- 副标题：`MadSpace 代运营服务`
- 日期：当前日期

### 总体拍摄原则（固定 boilerplate，每次不变）

> 1. **中长镜头范围**：取景不要太近，以便于设计做图  
> 2. **构图**：与人的身体（如手臂）相结合，使图片更有趣，显得产品更实用；注意不要有多余夸张表情  
> 3. 对产品进行**多角度拍摄**，有必要突出产品的特点  
> 4. **背景**：杂乱背景可虚化处理；尽量采用干净整洁的背景；也可选择纯色背景，与产品相近或互补  
> 5. 可以采用**对角线拍摄**，使产品看起来更加灵活  
> 6. 也可以选择与产品相关的物体  
> 7. 拍摄时**加强产品的视觉冲击力**，不要拍得过于板正  
> 8. **不要竖屏的照片**（所有照片必须横屏，图片长宽比建议 4000×3000）

| 序号 | 项目描述 | 要求 |

**脚本建议**（结构固定，内容替换变量）：

- **开场**：痛点场景镜头（根据产品功能推断用户痛点）

**拍摄要求**（固定 boilerplate）：
> 每个场景需包含完整使用流程 / 捕捉自然光线下产品质感 / 确保功能演示清晰直观 / 所有功能必须真实演示 / 温度/数据参数显示清晰 / 场景转换自然流畅 / 模特表情真实自然 / 重点突出产品便携性和核心功能特点

### 三. 设计生产运输拍摄（8 个子项，顺序固定）

| 序号 | 项目描述 | 要求 | 数量 |
|---|---|---|---|
| 1 | 产品正常运转画面（平台审核用） | 实拍视频，产品亮灯/屏幕亮起/运转状态，时长稍长 | `{{生产图_运转视频数量}}` |

## 输出规范

1. **文件格式**：工作稿为单个 `.html` 文件，客户交付优先为单页长图式 `.pdf`
2. **视觉风格**：白底，绿色/蓝色表头（参考模板），专业表格布局，A4 打印友好
3. **参考文件列**：沿用当前确认版排版，参考列宽 `260px`，图片完整显示不裁切；产品静态图实拍 + 渲染模块默认全部使用项目专属 AI 生图；生产/运输类参考图可继续使用 `assets/static-references/` 固定参考图；缺图时放灰色占位框，标注"[请插入参考图]"
4. **PDF 交付**：默认生成单页长图式 PDF，避免 A4 分页导致大面积留白；确保参考图完整显示、不裁切
5. **不要输出 markdown 表格给用户**，直接生成 HTML 文件和客户交付 PDF
6. 生成完毕后用 `present_files` 工具交付给用户
7. 同时提供一句话总结：共几个章节、几条拍摄指令、预计交付物数量范围

## 错误处理

- 用户没有提供某项信息，填入 `【待确认：{字段名}】` 并用黄色高亮
- 产品类型非户外/消费电子，照常生成，但在文档顶部加注："本模板以户外/消费电子类产品为基础，请根据实际产品类型调整场景描述"
- 用户要求修改某章节 → 只重新生成该章节对应的 HTML 片段，询问用户是否要更新整个文件

# 众筹方案网站 Crowdfunding Proposal Site（形式 + 内容 合并版）

> **本 skill 合并了两个老 skill**：`crowdfunding-proposal-site`（**形式**：滚动网站、3D 主角、动效）+ `crowdfunding-plan-html`（**内容**：策略分析方法论、定价/预算/KPI）。
> **形式一律** = 硅谷浅色滚动网站（本文 tokens ＋ 母版 CSS，视觉基因以 `viaim-conclusion-scrub.html` / `vocci-conclusion.html` / `meeting-graph.html` 为准）。⛔暖土色/Patagonia 主题已于 2026-07-30 删除，不再提供第二套视觉。
> **内容深度** = 需要完整商业分析时，开工前先读 `reference/content-methodology.md`（这是"内容更全"的来源，原 plan-html 的全部策略方法论沉淀于此）。

## 触发条件
用户要求把众筹提案/整体方案/pitch 做成网页、滚动网站、单文件 HTML 交付时使用本 skill。典型表述:"做一个 XX 式的方案网站""把这份规划做成网页""要滚动动效的提案页""做一份众筹方案的HTML""可行性方案""市场调研版"。无论是**对内汇报/老板审阅**、**对品牌方的代理提案(Mode A)**，还是**面向 backer 的国际众筹页(Mode B)**，都走本 skill。

## 产出标准
单文件 HTML(字体走 Google Fonts CDN;**⛔3D 不走 CDN importmap——three.js 必须内联进文件**,否则用户在预览面板/受限环境打开时 CSP 拦掉 CDN、3D 完全不显示且无报错,见 PITFALLS #41),双击可开,可直接拖 Netlify Drop 部署(提醒用户点 Rename and deploy 改成 index.html)。图片压缩后 base64 内嵌,整文件尽量控制在 500KB 量级；若客户给了多张广告素材、KOL缩略图或职业照片,以视觉完整优先,压缩后再内嵌。

## 内容框架先定 Mode（开工前判断，决定全文口吻与必备章节）
- **Mode A · 代理对品牌方提案（默认，MadSpace/中国出海众筹机构）**：HTML 是给**中国品牌客户**看的提案 deck，不是给 backer 的页面。正文**全中文**(产品名/slogan/平台名/无中文对应术语可留英日)；框架是"为什么众筹 / 怎么执行 / 预期结果"；必备分析章节：定价策略(含单位经济表)、目标市场与受众、资金需求与预算、竞争优势拆解。预算只展示**纯营销费用**。语气是策略总监在会议室里的专业中文，用"我们"做代理判断。
- **Mode B · 国际 backer Campaign 页（用户不是中国代理时）**：消费者向的 campaign landing page，英文，benefit 语言面向 backer。
- **B2B/企业级产品需要消费众筹重定位**时：先读 `reference/b2b-repositioning.md`(方法论) + `reference/b2b-claims-checklist.md`(claim 核验)，案例见 `reference/c2000-case-study.md`。
- **可行性方案/市场调研版**（用户说"可行性方案"而非完整执行方案）：出更短的 11-12 章 deck，方法见 `reference/cp-feasibility-study.md`。
- **敏感品类**（成人/亲密、医疗等）：封面用抽象/排版式装饰几何，**绝不出现产品图或插画**；社群调研泛化表述("海外主流用户社群调研"不点名具体 subreddit/论坛)；分析严谨度与其他品类一致，敏感只体现在视觉与命名。

## 第一步永远是:定主角的运动语法
动效语言跟着产品的使用语法走,先判断产品属于哪一类,再决定滚动叙事的主角怎么动:

| 类型 | 例子 | 运动语法 |
|---|---|---|
| 被佩戴/陪伴的 | 戒指、手表、耳机 | 主角全程漂浮跟随,姿态随章节插值(POSES 系统) |
| 被操作的工具 | 相机、键盘、CNC | 产品定住,机位走:滚动驱动镜头推拉摇移,全身→部件特写 |
| 价值在输出的 | 相机、投影、打印机 | 用产出当画布:样片铺屏、取景框线、失焦→合焦入场、光圈/快门转场 |
| 价值在动作的 | 机器人、筋膜枪、外骨骼 | 让那个动作本身动,而不是产品空转 |

主角层实现选型:几何简单(戒指)→ 程序化 LatheGeometry 实时 3D;细节复杂(相机/机器人)→ 预渲染视频滚动擦洗或序列帧,其余引擎照用。**⚠️程序化建模必须逐项对着真机图核形**——把官方图渲成 260dpi 大图,列出剖面形状/倒角/表面处理/logo 位置与做法/传感器结构/内外壁材质差异逐条实现,建完并排贴真机图比对再交付(实测凭印象建的剖面被打回「产品图不对」,详见 PITFALLS #42)。

## 版式两档(先问用户要哪档,默认结论版)
- **结论版(默认,对内汇报/老板审阅)**:章节 ≤10、每章一屏一结论;标题用 `.mk` 荧光标记结论词;受众+痛点合并一页(受众一行四格+痛点快读列表+粘性侧图);市场时机+竞品+差异化合并成**一张三列对比表**(竞品|它的主场|我方立场,立场列加粗);删纯装饰小字(封面说明段、预算行小注、与档位策略重复的卡内行)。
- **叙事版(对外展示/路演,明确要求时才做)**:钉屏场景切换、粘性堆叠卡、特写章等"时间型"模块全开。注意:时间型模块在内部汇报场景会被嫌"花时间没重点"——这是真实老板反馈。

## 客户可见文案红线
- 客户交付版只能出现最终商务判断、数据、执行动作和交付物,不得出现内部沟通、修改记录、制作说明、代理商自我批注或对用户反馈的复述。
- 全文禁用内部过程词和提示词痕迹,包括但不限于:`这一页`、`本页`、`原 01`、`原 04`、`合并`、`改成`、`改为`、`不需要`、`重新`、`待确认`、`备注`、`修正版`、`预览`、`生成`、`导出`、`脚本`、`内部`、`客户看到`、`原型`、`透出`。
- 英文阶段名统一用 `pre-launch`;不得在客户可见文本中使用 `preheat` 或 `prelaunch`。若用户要求时间线阶段名中文化,阶段名写 `筹备期`、`预热期`、`众筹期`。
- 避免 AI 套话句式:`不是...而是...`、`并非...实则...`、`A...B...` 对照式空话。改成直接业务陈述,例如目标、预算比例、预计 Leads、CPL、订金、转化率、Reward 拆分、来源拆分、时间线、KOL矩阵、素材。
- 页面标题、眉题、导航、图例、卡片说明、表格脚注等所有可见文字最小 14px;若小字显得挤,删掉装饰小字或重排,不要降字号。
- 最终交付前必须对源代码和渲染后的 `document.body.innerText` 同时做禁词扫描;命中后先改文案再交付。
- 客户可见页面不得写出需求来源或内部执行状态,包括 `用户指定`、`用户要求`、`已纳入`、`模型以`、`按用户反馈`、`配套 Excel` 这类只对内部协作有意义的口吻。预算页、目标页、改动后的章节只能写最终商务口径,例如 `目标按 30% 营销预算配置`。
- 禁"评语式口吻"——对客户项目/品牌下内部评价的句式,如 `本项目少有的`、`常被忽略的`、`难得的亮点`、`居然/竟然`:隐含"项目本来不行"的贬义,发给品牌方即失礼。改写为对外商务表述,把比较对象换成竞品/同品类("同品类 campaign 很少能给出的交付承诺"),或直接陈述资产("另一项可以直接调用的信任资产")。QA 时与禁词一起扫:`少有`、`常被忽略`、`难得`、`罕见`、`居然`、`竟然`。

## 工作流(10 步)
1. **吃产品**:抓官网核实全部参数,下载产品图研究工业设计(轮廓、分割线、按键、配色 SKU),建模/选素材前先看图。
2. **定 Mode + 运动语法**(上两节)。
3. **参考母版锁定**:若用户上传或指定一份已有方案 HTML/PPT/PDF 作为参考,必须把它当成母版,沿用其页面顺序、模块类型、标题层级、卡片/表格表达、KOL 卡片形式、预算/漏斗/时间线呈现方式;只替换项目内容和数据。不得另起一套版式、另做一版结构,除非用户明确要求重新设计。
4. **内容核对**:所有数字加总与占比=100%;客单×支持者≈目标金额;前后口径一致;外部数据(竞品营收、众筹纪录、YouTube播放/互动/订阅)必须搜索核实并附来源链接;交付版删除一切内部口径,只保留外部商务表述。**深度商业分析(定价/预算/KPI/可行性)按 `reference/content-methodology.md` 执行。**
5. **设计系统**:浅色硅谷风 tokens(见下);深浅反转留给定价等关键章做"插曲";MadSpace logo 两处低调(封面 Prepared by + 页脚);站点 UI 避免大面积绿色,但 Kickstarter/广告素材自身用色可保留。**卡片样式硬规则(2026-07-30 用户打回后拍板):直角卡 border-radius:0,圆角只允许圆点/头像的 50% 与 ≤2px 小件(chip/badge/进度条);1px 发丝边 var(--hair)+柔双层投影 `--shadow:0 1px 2px rgba(20,22,28,.04),0 14px 36px rgba(20,22,28,.07)`;tokens 与组件 CSS 从母版(viaim/vocci/meeting-graph)整段复制,⛔不得凭 token 摘要"等效重写"——实测重写必漂(圆角卡+单层薄投影被打回,见 PITFALLS #39–42)。**站点底盘交互层(卡片 hover/弹层/手风琴/骨架屏/入场)默认按 `reference/craftwork-motion-system.md` 执行**——纯 CSS 克制微交互,JS 只切状态;3D/滚动主角引擎不受影响。
6. **章节映射**:提案页数→8-13 个网页章节,左侧 mono 编号导航 rail;每章按内容选模块(见模块清单)。若存在参考母版,章节数量和编号优先跟母版一致。
7. **构建**:bash heredoc 分块写入,每块后 wc -c;JS 写完提取 module 做 node --check。
8. **文案润色(每个方案必跑,2026-07-30 拍板)**:构建完成后、QA 之前,调用 `chinese-business-copy` skill 把全站客户可见中文文案整体过一遍——去翻译腔、去口语化、正式但不僵硬,改动回写 HTML 再进 QA。修改已有方案时,被改动的章节同样要过一遍。(Mode B 英文页不适用。)
9. **QA**:playwright 截图自查(见 QA 清单)。
10. **交付**:保留一个工作文件,再同步一份到用户指定交付路径;提醒联网打开、Netlify 改名 index.html、可改站点名。若修改已有 HTML,先改工作文件,QA 通过后覆盖交付文件。

## 设计 tokens(默认:浅色硅谷风)
- 底:#FAFAF8 / 卡:#FFFFFF + 1px rgba(23,24,29,.1) 边 + 柔投影
- 字:ink #17181D / mut #4E545E / faint #6F7580(最浅灰对比度必须 ≥4.5:1)
- accent:饱和蓝 #2B50E0(与 MadSpace 蓝同语系);深色插曲 #8093EF
- 深色插曲:#101218 底
- 字体:Noto Serif SC(标题/立场句)+ Noto Sans SC(正文,**禁用 300 细体**)+ IBM Plex Mono(数据/眉题);所有可见文字最小 14px,包括左侧 rail、眉题、图例、表格脚注、卡片内小字
- 层级靠"字号+色阶",不靠细体和过浅灰;**默认正文别太小**:lede ~21-23px、正文/表格/卡片/列表 ~15-16px;**章节名做大标题**(~40-62px 衬线),"一页一结论"句做其下副标题(用户反复要求"标题突出/内文放大",默认给够)
- 重点标记 `.mk`:linear-gradient(transparent 62%, var(--acc-dim) 0) 荧光笔效果,每章标题的结论词必须标记
- 章节标题层级必须固定为:章节编号/模块名(如 `04 / Funding Models`)在上,该章节大标题紧跟在其正下方;不要把编号放左列、标题放右列。若用 grid 做内容排版,也必须让编号与标题保持同一纵向阅读轴。

## 内容硬规则
- **竞品话语权**:大标题/立场列永远是我方立场句(从"应对"文案提炼),竞品名只进眉题或表格首列;不在竞品章引用对方营收等强数据(那类数据放市场验证章并附来源);钉屏时加常驻定位锚让我方定位始终在屏。
- **竞品分析**:优先使用用户提供的 Excel/表格作为竞品数据源;竞品数量不足、字段无效或比较维度偏少时,补齐为可决策的对比表。面向 AI recorder / AI notetaker / 办公 AI 产品时,至少覆盖 Plaud、Otter、Fathom、Limitless、Bee/同类穿戴记录器等可比对象,并用价格、硬件形态、录音/转写、工作流、隐私、本地留存、订阅和众筹表现做横向比较。用户指出刷单、异常或不可作为参考的项目必须从竞品分析、比较表和结论引用中删除;Voxmate 同类方案中不要把 TicNote Pods 作为有效竞品案例。
- **竞品三锚点**:竞品比较表下方必须保留三张决策锚点卡:价格锚点、形态锚点、叙事锚点。价格锚点说明主力价/订阅/客单如何被竞品验证;形态锚点说明硬件形态与可被理解的品类参照;叙事锚点说明我方从竞品叙事中避开什么、强化什么。除非用户明确删除,不得省略。
- **章节压缩**:删掉空泛的"营销目标与执行框架"类页面;把核心判断与产品证明合并,把受众、痛点、使用场景合并,把目标、预算、KPI和执行动作放进数据页/时间线/预算页。客户页不解释"为什么合并",只呈现最终结构。
- **受众表达**:受众页用四张并排真实职业照片或 GPT-image 等高质量生成照片表达目标人群,不要用抽象插画占位。AI办公/记录类默认四类:B2B销售/外勤、顾问/项目经理、管理者/创业团队、创意/跨语种工作者。若用户指定美国市场,画面应呈现美国办公/外勤语境;若用户明确指定美国白人职业形象,按该人群生成实际职业照片。
- **受众照片是完成条件**:受众页只有文字卡、图标、抽象插画或空白占位时,交付未完成。若没有客户提供照片,必须先生成或寻找四张高质量职业人物照片并嵌入页面,再做 QA。
- **价格与行动**:定价页写价格锚点、Reward结构、主力档、数量策略和行动路径,不要把价格卡写成产品卖点。**KS 档位阶梯(默认,价格从低到高)**:`Secret Reward(订金专属)` < `Launch Special` < `Super Early Bird` < `Early Bird` < `Late Pledge(众筹结束后开放)`。**Launch Special 是主力销售档,销量占比 ≥60%**,支持者数与 AOV 测算的主力客单以 Launch Special 价为准;Secret Reward 是全场最低价,只对付订金用户开放,台数=订金付款人×上线转化率;SEB/EB 依次抬高,承接主力档售罄或涨价后的购买;Late Pledge 档内最高价(仍低于零售锚点),众筹结束后才开放,不计入冲刺目标模型。梯度参考:Secret ≈ LS − $20,SEB/EB 逐级 +$50 上下,零售价另作价格锚点。各档数量按目标金额反推,不同目标(`$600K` vs `$1M`)不得复用同一数量假设。
- **页面叙事**:若用户要求"页面叙事",用英文写成多行标题与内文,每条对应 Kickstarter 页面首屏、痛点、新品类、AI价值、硬件可信、目标人群、FAQ/风险解除等实际页面内容,避免中文内部说明。
- 日语必须本地化校对(実体ボタン→物理ボタン 这类);LINE 公式アカウント等术语用对。
- 竞品/数据来源链接用 mono 小字 `.srcline`。

## 美国众筹商务方案默认模块
面向 Kickstarter/Indiegogo 美国市场方案时,除用户另有要求,按下列模块组织并保证每页有可执行信息:

- **封面**:产品名 + `U.S. Crowdfunding Plan` 或用户指定标题,保留产品主视觉/3D背景主角;除非用户明确删除,不要拿掉原本可用的背景 3D 渲染图。
- **品类判断 + 产品证明**:用一句外部可见定位句说明产品占位,再用 3-4 个证明卡说明随身捕捉、可信留存、拾音能力、工作流结果。
- **受众与场景**:四类目标职业图 + 每类场景需求;下方可加一句简短品类边界,例如 `Plaud = recorder hardware`, `Otter = meeting software`, `Voxmate = wearable capture + local core + workflow assistant`。
- **竞品与比较**:使用用户表格优先,横向比较足够多竞品和关键字段;减少无效介绍文字,增加可比较字段。
- **定价与行动**:展示 Reward 和主力价格,不写成卖点;价格与 AOV、支持者数量、目标额可以互相校验。
- **页面叙事**:用英文多行标题/正文表达 Kickstarter 页面讲述顺序。
- **渠道组合**:用清晰圆饼图展示订单来源,右侧逐条解释每一类来源。默认来源占比:众筹平台流量 45%、众筹期投放 30%、预热 Lead 转化 10%、其他 10%、众筹社区 3%、PR/KOL 2%。圆饼图不可照抄参考图黑底样式,标签不能重叠。
- **预算模型**:分别计算 `$600K` 与 `$1M` 两套模型;`$600K` 默认营销费用率可用 17.96%,`$1M` 默认提升到 20%。必须给出预计 Leads、CPL、订金数量、预热转化数量、预热转化率、每个 Reward 转化数量、每个来源转化数量。预热转化率默认 2%;订金要分清**两个不同的率**,不要混用:① **Lead → 付订金率**按订金档:`$5` 档 **10%**、`$10` 档 **5%**;② **订金 → 上线购买率**整体落在 **30–60%**,按订金金额高低取值——订金越低承诺越轻、转化越低,`$10` 档取 **30–40%(保守取 30%)**,**不要用 50%**(2026-07 品牌方口径修正)。(若用户给出新比例则覆盖。)预算和订金相关表格统一写 `预热 Lead 数` / `预热 Lead 转化`,不得写 `预热邮箱数`。**17.96% 的逐项拆分(预热广告4.4%/上线广告8.72%/KOL2.4%/媒体0.4%/社群1.44%/工具0.3%/抽奖0.3%)见 `reference/content-methodology.md`。**
- **订金策略**:放在 `预热转化测算` 后段,用表格或时间表写清楚金额、最低价格、赠品和执行路径。默认两档为 `$5` 与 `$10` 订金;付款后用户锁定 `Secret Reward` 档(全场最低价,低于 Launch Special)和 `6 个月免费会员` 或等值赠品。订金页从 `pre-launch` 第 1 天完成,第 1-4 周持续走两条路径:用户在预热页留下 Lead 后通过弹窗进入订金页,以及独立投放订金页;第 1-4 周同步社交媒体订金优惠信息;最后 1 周邮件触达未付订金 Leads;上线第 1 周向订金用户发送 Secret Reward 链接。Voxmate `$600K` 模型默认用 `13,100` 预热 Lead 数直接计算并给出结果:`$5` 订金 = `13,100 x 10% = 约 1,310` 订金付款人,上线购买 = `约 1,310 x 30% = 约 393`;`$10` 订金 = `13,100 x 5% = 约 655` 订金付款人,上线购买 = `约 655 x 30% = 约 197`(**上线转化取 30%,不是 50%**)。其他项目若没有用户指定 Lead 数,先用对应模型的预计 Leads 计算,不要只写公式。
  - **订金档数量会反向封顶 Reward 梯度**:Secret Reward 是订金专属档,它的台数 = 订金付款人 × 上线转化率,不能凭空写。改订金金额或转化率时,**必须连带重算 Secret 档台数、把差额挪到下一档、并同步 blended AOV 与全站所有 AOV 引用**(实测这条最容易漏,改了金额忘了改率、改了率忘了改梯度)。
- **KOL矩阵**:分别列 `$600K` 与 `$1M` 配置,用好看的表格/卡片排版展示头部、腰部、KOC数量和配套样机数量。不要把拍摄/功能 demo 样机写进这个数量。
- **KOL预找**:必须到 YouTube 搜做过竞品内容且播放量高的具体创作者,不能只写频道方向或品类方向。展示 6 个以内优先候选,上下两行、每行三张卡。每张卡必须包含圆形头像、竞品视频封面、频道名、订阅数、具体视频标题、视频观看量、点赞/评论/公开互动量或可得互动指标,并附视频链接。若用户上传的参考方案已有 KOL 卡片表现形式,必须复用同一种卡片结构、字段顺序和视觉节奏。数据必须标注来源或说明缺失,不得编造。
- **广告预算分配与受众**:展示 `pre-launch` 和 `Launch` 两个圆饼图,图上必须同时标出 Meta/Google 名称和比例。默认 `pre-launch` 与 `Launch` 两图均为:Meta 90%、Google 10%。圆饼图不要放白底方块里,以浮动图形或轻容器呈现。受众写美国 35-60 岁高意图人群:第一圈层销售岗位(房产经纪人、房产销售、B2B销售),第二圈层决策者(CEO、Business Owner、高阶管理者),并补充预计投放受众规模。
- **广告素材**:若用户提供 5 张 1:1 Meta广告图,直接使用并放在"广告预算分配与受众"模块下方;不要在每张图底下再写文字说明。若需要制作素材,参考用户给的广告结构和产品图,做 5 张 1:1 点击导向 Meta 素材。
- **时间线(三件套,顺序固定)**:① 上线 0–48h 作战窗口 → ② **全案周计划表(甘特矩阵,主模块)** → ③ 周级竖向时间线 → ④ 筹款节奏柱状图。**完整规格见 `reference/timeline-gantt.md`,做时间线章前必读。**要点:
  - **甘特表是客户最认的形式**(真实反馈:表格形式最好)。列 = **自然周**(写「7 月第 3 周」不写「W1」),三层表头(阶段→月份→周),首列 sticky;必须含 **「必备前置 · 品牌方」**(素材授权、样机备货两项;⛔实体注册/收款账户/Meta BM 开户/平台协议这类开户注册事项不写,2026-07-30 拍板)与 **「发货期」**两组——最常漏、也最被在意。关键节点用 ◆ 独立成行。档期变体用**实心 vs 斜纹**在同一张表里表达,不做两张表。
  - **竖向时间线是周级颗粒度**:筹备期与预热期各拆 4 周,众筹期按档期拆 4/6 周,**每周写具体动作**;只给三个阶段节点会被打回"不够详细"。圆形节点圆心必须压在中轴线上(交付前实测偏移=0)。
  - **众筹期默认 30 天 / 45 天两档,不再默认 60 天**(实测客户会直接砍掉 60 天版)。30 天首 72h 冲 40%、KOL 集中释放;45 天首 72h 冲 35%、KOL 分批。上线期广告两档总额相同,30 天版日均 +50%。
  - **KOL 排期必须与名单容量对得上**:达人通常一人一条视频,「每周 N 条 × M 周」总数不得超过 KOL 矩阵的达人总数——这是甲方一眼能算穿的自相矛盾。
  - 「评测样机寄送」排在**上线前 3–5 周**(寄送 1–2 周 + 视频制作 2–3 周)。样机数量在甘特表/KOL 矩阵/品牌方配合清单三处必须一致。
  - 筹款节奏柱状图:30 根柱模拟 daily funding,按档期给形状(30 天更陡、45 天中段更长),下配首周/中段/最后 72h 三张说明卡。
- **方案图谱(强烈建议加)**:方案是线性的,但会上老板是随机跳的。加一层图谱导航,客户提问时一点即到,还能顺带展示"这是个体系"。内容用 `cloneNode` 从正文取,**不另写一份**(避免同一数字两处出处)。母版 `reference/meeting-graph.html`。
- **可行性与物料**:列产品/量产、AI功能证明、内容生产物料等客户需要准备的材料;**认证与开户类内容一律不列**——品牌方合规认证、物流认证、平台认证(FCC/CE/技适/KC/ISO/SOC/物流资质/平台审核状态等),以及美国实体/主体注册、收款账户、Meta BM 开户充值、平台协议签署这类开户注册事项,都与方案无关,不进物料清单、信任章、时间线或任何章节;不要展示本次方案制作工作本身,也不要展示"一套可复用叙事体系"这类 agency 内部交付说明。

## 内容方法论（深度商业分析 · 来自原 plan-html）
做 Mode A 代理提案或任何需要"内容更全"的方案时,**开工前读 `reference/content-methodology.md`**。它覆盖：
- **预算公式(硬规则)**:营销预算 = 目标 × 17.96%(逐项拆分;目标 $1M 及以上用 20%);目标≠营销预算;按钮标注两个数(如"目标 $500K · 营销预算 $89,800");禁止编预算数。**默认目标档位:一般市场 $500K/$1M,美国市场 $600K/$1M。**
- **KPI 一致性(硬规则)**:支持者数 = 目标 ÷ 主力客单(Launch Special);AOV 与主力定价档对齐;每个 KPI 下加一行推导注释。不一致即为错。
- **定价方法论**:找 KS 价格锚点 → 五列竞品定价表 → spec-gap 双方案 → 档位阶梯(Secret Reward < Launch Special 主力≥60% < Super Early Bird < Early Bird < Late Pledge) → Add-On vs Bundle → 单位经济表(BOM→margin→volume→contribution) → 反国内背书溢价 → 预算章只放纯营销费。锁定入门价的规模优先定价见 `reference/cp-scaling-pricing.md`(客户锁定价即 Launch Special 位)。
- **spec-gap 决策闸(硬件必备)**:产品对锚点竞品有可见规格劣势时,定价讨论前先插一个决策闸 box,强制品牌方先决定。
- **认证与开户类内容一律不写**:品牌方合规认证/物流认证/平台认证(FCC、CE、技适、KC、ISO、SOC、物流资质、平台审核等)与实体注册/收款账户/Meta BM 开户/平台协议类开户注册事项,均与方案无关,不进方案任何章节。
- **数据来源标注**:每个量化声明(市场规模/CAGR/流量份额)后接一行来源小字,否则一问就塌。
- **可行性判断 section**:主结论 + 为什么可行(3卡) + 关键前提 + 建议判断(一句话收口)。
- **战略判断型章节**(Mode A 显成熟度):Winning Logics 三列、"策略边界:不主讲什么"(暗底)、"Campaign结束后的品牌资产"五列、"品牌方关键配合清单"。

- **章节级编辑安全**:禁短数字串全局替换(`$220` 会污染 `$220–240`);客户交付删一切内部 shorthand。

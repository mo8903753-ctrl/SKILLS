# 众筹方案 · 内容方法论（深度商业分析）

> 本文件是从原 `crowdfunding-plan-html` skill 沉淀下来的**策略方法论**，与设计/形式无关。
> 做 Mode A 代理对品牌方提案、或任何需要完整商业分析深度的方案时，开工前读本文件。
> 形式（滚动网站）见 SKILL.md；视觉一律硅谷浅色母版基因（暖土色主题已于 2026-07-30 删除）。

---

## 0. 两种内容框架（先定 Mode）

### Mode A · 中国代理对品牌方提案（默认）
HTML 是给**中国品牌客户**看的提案 deck，不是给 backer 的页面。
- **语言**：正文全中文。仅产品名、slogan、平台名（Kickstarter, Makuake）、无中文对应的技术术语可留英/日。
- **框架**：代理对品牌的 pitch —— "为什么要众筹 / 我们怎么执行 / 预期什么结果"，不是面向消费者。
- **必备分析章节**：
  - 定价策略分析（含单位经济表：BOM → margin → 目标量 → margin 贡献）
  - 目标市场选择与受众分析（按地区优先级排序 + 受众画像）
  - 资金需求与预算方案（双档预算切换 + 费效预测 + 选档逻辑）
  - 竞争优势拆解（雷达/二轴定位图 + 特性对比表 + 逐竞品文字分析）
- **预算展示**：只展示**纯营销费用**，不含平台费、服务费、BOM。
- **语气**：专业商业中文——策略总监在会议室 pitch，自然段落带连接词，不要短促陈述句堆叠，用"我们"做代理判断。

### Mode B · 国际 backer Campaign 页
消费者向 campaign landing page，英文，benefit 语言面向 backer。标准 14 章结构（封面/Exec Summary/市场/产品/竞品/受众/叙事/Perks/营销组合/落地页/预算/时间线/KPI&风险/物料）。

> **14 章 vs 网页章节（孰先）**：标准 14 章是内容清单蓝本。做滚动网站时，按 SKILL.md「版式两档」与「章节压缩」把它压缩/合并为 **8-13 个网页章节**（结论版 ≤10）——滚动站的章节数以压缩后为准，不必硬凑 14 章。

## 1. 预算公式（硬规则 · 禁止编数）

**营销预算 = 众筹目标 × 17.96%**（基准费率；目标 **$1M 及以上提升至 20%**）。目标 ≠ 营销预算，二者必须分开。

> **默认目标档位**：一般市场 **$500K / $1M**，美国市场 **$600K / $1M**（与 SKILL.md「美国众筹商务方案默认模块」一致；Panel A = 较低档默认激活）。下文出现的 `$200K`/`$35,920` 之类数字仅为**公式演示**，不是默认档位。

| 项目 | 占目标 % |
|------|----------|
| 预热广告 (30d) | 4.40% |
| 上线广告 (45d) | 8.72%（Meta 90% / Google 10%） |
| KOL 合作 | 2.40% |
| 媒体新闻稿 | 0.40% |
| 众筹社群 | 1.44% |
| 营销工具 | 0.30% |
| 抽奖奖品 | 0.30% |
| **合计** | **17.96%** |

规则：
- 双档切换按钮**必须同时标目标和营销预算**，如 `目标 $500K · 营销预算 $89,800`、`目标 $1M · 营销预算 $200,000`（$1M 按 20%）。
- 预算表每行带"公式"列（如 `$500K × 4.4%`）+ "说明"列（平台拆分 Meta/Google 90:10、CPL $3-5、ROAS 2.5x）。
- 预算章只放纯营销费，加注："不含 Kickstarter 平台费 (5%)、支付处理费 (3-5%)、产品 BOM、物流和品牌方内部人力。"
- **美国市场双目标模型**：`$600K` 用 17.96%，`$1M` 提升到 20%；并给出 Leads、CPL、订金数、预热转化数/率、各 Reward 与各来源转化数（默认值见 SKILL.md「美国众筹商务方案默认模块」）。
- 锁定入门价的规模优先定价 → `cp-scaling-pricing.md`。

## 2. KPI 一致性（硬规则）

KPI（支持者数、平均客单）**必须从定价档推导**，不能凭空写。
- **支持者数 = 目标 ÷ 预期平均客单**。例：$200K ÷ ~$999 主力档 ≈ 200 backers，**不是** 1,500。
- **平均客单 (AOV) = 与主力定价档对齐**（主力档 $999 + add-on 拉升 → $900–1,100）。
- 若支持者数与 AOV 无法回到目标金额，数字就是错的。
- 每个 KPI 下加一行灰色推导注释："按主力档 $999 计需 ~200 backers"、"主力档 $999 为主 + add-on 拉升"。
- 时间线里的 email/Leads 目标也要从预算公式推导，不写孤立的"5,000+"。$500K → "积累 4,400–6,600 Leads"；$1M → "8,800–13,200 Leads"。
- **哪个价是 AOV 基准**：支持者数/AOV 以**主力档 Launch Special** 为准（销量占比 ≥60%，见 §3 档位阶梯）。本节 `$999` 是 NAS 案例示例值，非通用值。`Secret Reward` 是订金专属引流档，**不作 AOV 基准**；SEB/EB 高于 Launch Special，承接主力档售罄或涨价后的购买。

## 3. Mode A 定价方法论（8 步）

1. **找 KS 价格锚点**：同品类已完成 KS/IGG 的最近直接竞品，其 SEB/EB 价就是消费者比较框架，决定市场可接受的天花板。
2. **建竞品定价表**：5 列（竞品 / 定位 / 关键规格 / 众筹价 / 零售价），4-5 个竞品，至少含一个 KS 已验证锚点、一个成熟品牌、一个低价替代。表下加来源小字。
3. **判断有无规格差**：若对锚点竞品有可见规格劣势（如 1GbE vs 10GbE），给两个方案——方案A（推荐，若 KS 版能升级规格则定在锚点价并以其他特性差异化）、方案B（规格差不可避免则降 $100-150）。
4. **Reward 档位阶梯（KS 默认，价格从低到高）**：`Secret Reward（订金专属）` < `Launch Special` < `Super Early Bird` < `Early Bird` < `Late Pledge（众筹结束后开放）`。**Launch Special 是主力销售档，销量占比 ≥60%**，主力客单 / AOV / 支持者数全部以它为基准；Secret Reward 是全场最低价，台数 = 订金付款人 × 上线转化率，不能凭空写；SEB/EB 依次抬高，承接主力档售罄或涨价后的购买；Late Pledge 档内最高价、只在众筹结束后开放，**不计入冲刺目标模型**。梯度参考：Secret ≈ LS − $20，SEB/EB 逐级 +$50 上下，Late Pledge 低于零售锚点价。
5. **Add-On vs Bundle**：硬件类（NAS/路由）**Diskless 基础档 + Add-On 菜单**持续跑赢默认 Bundle。Diskless 压低入门价拉宽漏斗，Add-On 在结账时抓已承诺用户。参考 UGREEN 2024 KS：~65% Diskless 台数 / ~50% 营收。
6. **单位经济表**：KS 价 → 估 BOM → margin% → 目标量 → margin 贡献 → 合计。BOM 近似也要给框架，注明"待品牌方提供完整 BOM 后精算"。
7. **明确反国内背书溢价**：**不要**用国内市场背书（信创、国家级实验室、中科院）作 KS 定价溢价——它们是叙事里的信任元素，不是涨价理由。KS 用户比的是 price-to-specs。
8. **预算章分离**：营销预算章只放纯营销费（见 §1）。

### 3.5 Reward 梯度的形状规则（写梯度表前先过一遍）

**梯度成员**（从低到高，价只在众筹页内有效）：
`Secret Reward（订金专属）` → `Launch Special`（上线首日，主力）→ `Super Early Bird` → `Early Bird` → `Late Pledge`（结束后补单）→ 双人/多件装。

- **众筹页价格上限 = Late Pledge，不是日常零售价。** 日常零售价是上线**之后**官网卖的价，**绝不作为一档写进 Reward 表**。它只出现在价值锚点语境：与竞品零售价横比、并说明"众筹全程低于零售"。（PITFALLS 31）
- **量的形状**：Launch Special 是量的峰（**≥60%，2026-07-30 拍板，旧口径 ≥35% 作废**），SEB/EB 依次递减，**Late Pledge 是补单档，应当最小**；Secret 是订金锁定的小档，台数被漏斗决定。出现"Late Pledge 比 Early Bird 还多"就是形状错了。（PITFALLS 33）
- **订金档数量是被漏斗锁死的**，不能随便填：`订金档台数 = 订金人数 × 上线转化率`（$10 档取 30–40%，保守取 30%）。
- **定完必须跑三项校验**：① 从 Launch Special 起量随价递减 ② Launch Special 占比 ≥60% ③ `Σ(价×量) = 目标金额` 且 `Σ量 = 支持者数`、`加权 AOV = 目标 ÷ 支持者数`。

**改梯度 = 改全站**。AOV 与支持者数是全文引用最广的两个数，一处不改就自相矛盾。改完逐项扫：
hero 统计条 `data-n` · AOV 公式行 · 客单口径提醒 · 各 Reward 档转化表 · 来源结构（各来源 = 支持者数 × 占比，加总必须回到支持者数）· 漏斗尾注 · ROAS/CAC 计算 · 风险卡里的客单敏感度 · 可行性主结论 · 定价卡上的台数。

## 4. spec-gap 决策闸（硬件产品必备）

产品对 KS 价格锚点竞品有可见规格差（1GbE vs 10GbE、SATA vs SAS）时，**在两个定价方案之前**插一个决策闸 box（negative 左边框）：

```
⚠️ 决策前提：[规格名] 是否标配
这是整份方案最关键的产品决策。
[解释规格差在 KS 比较页上的影响]
建议：[可执行建议]。如果无法实现，方案A定价逻辑不成立——应采用方案B降档定价，并接受筹资规模可能下调30-40%。
```

强制品牌方在定价讨论前先做决定。没有这个闸，方案会读起来像两个方案都成立，而其中一个可能根本不成立。

## 5. 认证与开户类内容不入方案

品牌方的合规认证、物流认证、平台认证（FCC、CE、技适、KC、ISO、SOC 2、HIPAA、物流资质、平台审核状态等）**与方案无关，一律不写**——不进风险章、不进物料清单/品牌方配合清单、不进信任章、不做认证徽章墙、不列"认证状态/认证时间表"条目。
- **开户注册类事项同禁**（2026-07-30）：美国实体/主体注册、收款账户、Meta BM 开户充值、Kickstarter 平台协议签署——不进甘特表"必备前置"、不进时间线、不进配合清单。"必备前置 · 品牌方"只留素材授权、样机备货。
- 产品资料里带认证信息时同样不搬运；品牌方明确点名要求展示时按其指示单独处理。
- 风险章照常保留（品类误读、AI 能力证明、样机数量、BOM/价格、市场教育等），风险评级按项目实际判断。
- 风险卡用 3 行紧凑格式：**风险：** / **影响：** / **应对：** 各一句。

## 6. 数据来源标注

每个做量化声明的章节（市场规模 $3.5B、50M+ 创作者、78% 隐私担忧、12.4% CAGR、KS 流量份额）后接一行来源小字（`font-size:.73rem`，最淡灰）：

```
数据来源：Grand View Research (NAS Market 2024), Pew Research (Cloud Privacy 2024), Statista (Creator Economy), KS/IGG 公开数据
```

没有这行，方案看起来精致但客户第一个"数字哪来的"就塌。外部数据（竞品营收、众筹纪录、YouTube 播放/互动/订阅）必须搜索核实并附来源链接。

**KS 市场流量参照**：北美用 **60%** 作流量份额；其他地区用定性描述（"第二优先级"/"后续扩展市场"），**不要**精确百分比（EU 28% / AP 18% 这类加总 >100% 且无来源的已删）。定性排序（NA 第一、EU 第二、AP 扩展）足够。

## 7. 可行性判断 section（Mode A 推荐）

放在 KPI/风险之后、"策略边界:不主讲什么"之前。给品牌方一个明确 yes/no + 理由——策略总监在会上会给的东西。结构：
1. **主结论**（analysis-box, accent 边）：一段说清产品是否适合 KS + 正确切入角。若产品原生叙事（信创/B2B/政府）在 KS 不成立，直说并给重定位角度。
2. **为什么可行**（3 卡）：产品差异化清晰度、品类已有用户教育、目标受众的真实痛点。
3. **关键前提**（analysis-box, teal 边）：方案成立的必要条件——规格升级、英文 UI、样机可得性。
4. **建议判断**（analysis-box, accent 边）：推荐方案 + 一句话收口提炼整体策略。
   - 收口示例："C2000 的众筹机会在于把'企业级数据保护'压缩进海外创作者能接受的桌面设备和价格带里。"

进程：风险识别 → 可行性评估 → 边界定义 → 成功图景 → 资产清单。

## 7b. 时间线与上线执行

- **前置准备 pre-phase（必加）**：时间线开头永远先放 T-6→T-4 周「前置准备」（内容生产、KOL 预对接）。**视频生产属于前置期，不放进 Month 1。**
- **相邻阶段合并**：两个紧邻且强相关的阶段（如"评测解禁"与"上线当天"仅隔几天）合并成一个时间线条目，不拆两条。
- **Launch Day 0-48h 作战图**：在竖向时间线**上方**加一个 6 列横向网格，一眼看清 72 小时上线窗口：`T-72h`(KOL评测解禁/媒体通稿) → `T-24h`(邮件序列首轮/社群预热帖) → `T0`(KS上线/全渠道推送，**accent 边框**) → `T+2h` → `T+6h`(广告全量开启) → `T+48h`(目标 **30% 筹资完成**，**teal 边框**)。内容只含 KOL评测/媒体通稿/邮件序列/KS上线/广告/数据复盘，**不含 Reddit/HN/Twitter-X**。注意：这与"筹款节奏柱状图"是两个不同模块——前者是 0-48h 速览，后者是全程节奏，不互相替代。**时间线章的完整四模块规格（作战窗口 / 全案周计划甘特表 / 周级竖向时间线 / 节奏图）见 `timeline-gantt.md`；众筹期默认 30 天或 45 天两档，不再默认 60 天。**
- **样机数量跨章一致**：品牌方"需提供样机数"必须与计划 KOL 数对得上（如计划 5-6 位 KOL → "≥5 台评测样机 + 1 台拍摄备机"，不是"1 台预产样机"）。拍摄/demo 样机不计入 KOL 矩阵数量。

## 8. 战略判断型章节（Mode A · 显成熟度）

这些章节把"咨询级提案"和"中立报告"区分开。

- **Winning Logics（3 列论点）**：放在概览后。三个超大背景数字列，各答"为什么这产品能在 KS 胜出"。数字/标题用 accent/teal/gold 三色。
- **"策略边界:不主讲什么"（暗底）**：定义 campaign **不**主张什么——对品牌方最有说服力的一页，显示你想过风险与定位边界。典型项：不用国内背书作溢价、不claim 无法验证的性能、不把企业级设备定位成家用、不在软件生态上硬碰几十年的老牌。
- **"Campaign 结束后的品牌资产"（近尾，浅底，5 列）**：展示 campaign 结束后品牌**拥有**什么——不只资金，还有完整资产组合。**标题必须是"Campaign结束后的品牌资产"，不是"你得到什么"**（后者太直白口语，用户明确否决）。五项递进：钱 → 用户 → 信誉 → 资产 → 渠道冷启动就绪。
- **"品牌方关键配合清单"（替代/补充物料清单）**：按职能分类品牌方责任——产品决策(accent)/信任资产(teal)/转化资产(gold)/交付资产(negative) 2×2 网格。标题用"品牌方关键配合清单"。删与他处重复项（BOM 若已在定价章、样机数若已在 KOL 章）；认证/物流认证/平台认证类条目一律不列（见 §5）。

## 9. 渠道清单（包含 / 排除）

营销渠道章按 `crowdfunding-marketing-plan` skill 的清单：
- ✅ **YouTube / Tech Review**（最高 ROI）
- ✅ **第三方众筹社区**（24 家标准列表：Backermany, Backerspaces 等）
- ✅ **Meta + Google 精准广告**（pre-launch 与 Launch 均 Meta 90% / Google 10%）
- ✅ **Newsletter 赞助**（TLDR, Hacker Newsletter）
- ✅ **创作者社群 & 垂直媒体**（PetaPixel, Fstoppers 等）
- ✅ **PR & 媒体 Outreach**
- ❌ **不要**包含：Reddit、Hacker News、Twitter/X、Privacy/Security media——这些测试过并经用户明确删除。

## 10. claim 软化清单（避免事实核查与法律风险）

- 禁 **"首款 / 业界第一 / 绝对供给"** 类绝对最高级。软化："$999 以下少见的企业级数据保护桌面 NAS"。
- 禁 **"竞品需 18-24 个月追平 / 18 个月硬件护城河"**——这是判断不是事实。软化："竞品若要补齐 SAS 架构与 RAID-TP，需要硬件平台调整，短期内我方具备阶段性差异化。"
- 认证类 claim 不做"降级"处理——按 §5，认证内容（FCC/CE/技适/ISO 等）一律不出现在方案里。
- 夸张隐私声明（"零遥测、零账号、零中间人"）软化为"可本地部署，不依赖公有云账号；数据可保留在本地网络内"，除非文档明确写离线-only。
- 部署数量（"50+政企部署"）除非品牌方确认，用定性："多行业政企部署案例"。
- 规格 claim 一致性：RAID-TP 需 ≥3 盘，2 盘配置不能配 RAID-TP；SAS 双端口冗余表述要按盘型区分。完整核验 → `b2b-claims-checklist.md`。

## 12. 结论版合并配方 + 执行量化补全（实战沉淀）

**结论版合并（内部/客户快审的默认收法，减少"花时间没重点"）：**
- **痛点 + 受众 → 合成一页"目标受众"**：只一行四格人群（真实职业照 + 一句核心诉求），痛点/社群洞察不在此展开（放"创意板块"或降为一句人群筛选逻辑）。别用钉屏一卡一屏的痛点栈——老板嫌花时间。
- **市场时机 + 竞品 + 差异化 → 合成一张对比表**。两种表型任选：① 定位型 `竞品 | 它的主场 | 我方立场(加粗高亮)`；② 可行性型（更像营销方案）`竞品 | 众筹结果·筹款/backers/AOV | 定位 | 我方机会点`。宏观市场数字降为表前一句引子，不单独成大段。
- **章节标题层级**：章节名做大标题（~40-62px 衬线），"一页一结论"那句做副标题——见 PITFALLS.md #14。

**执行量化补全（要"内容更细/更像营销方案"时对标补齐）：**
- **产品证明卡**：判断/定位章放 4 张硬件证明卡（形态 / 核心能力 / 状态可信 / 续航或音质），用具体规格当证据，别只讲概念。
- **预热转化测算独立成章**：除总 KPI 外给三张表——① 各 Reward 转化数（∑=支持者数，反推 ≈AOV）；② 各来源转化数（45/30/10/10/3/2 × 支持者数）；③ $5/$10 两档订金口径（Leads×付款率 → ×上线转化率）。Leads = 预热广告 ÷ CPL($4)，Lead-to-pledge 2%。**付款率：$5 档 10% / $10 档 5%；上线转化率整体 30–60%，按订金金额取值，$10 档取 30–40%（保守 30%），不要用 50%。Secret Reward 台数 = 订金付款人 × 上线转化率，改任一参数都要连带重算梯度与 AOV。**
- **广告受众给可投放池规模**：Meta 一圈层销售岗 ~3-5M、二圈层决策者 ~4-7M、Google 高意图 ~250-500K、再营销池按模型 8K-80K。
- **竞品用真实众筹 AOV 当价格/可行性锚**：引真实 KS/IGG 案例的筹款额/backers/AOV（附 Kicktraq/BackerKit 来源），论证价带与"多少人即破百万"。

> 参照对标：营销方案型 deck（如 TonoCard）在"执行/量化"上很细（双模型、漏斗每档/每来源、受众池、6 条风险），但"战略/创意"薄（无创意板块/无宏观市场/受众只列人群）。提案型（如 viaim Rise）多创意板块 + Reddit 洞察 + 宏观市场；按用户要哪种重心取舍。

# 投标文件变体 · 方法论（莎士比亚 SPDTC20260720 全程沉淀）

> 场景：正式招投标（有招标文件/须知/评分表）。在 proposal-site 底盘上加一层「逐条应答」，但应答浓度要拿捏——以下每条都是甲方逐轮打回校准出来的。

## 1. 结构 = 严格对表招标清单顺序

- 三部分：商务响应 → 技术方案 → 报价响应，**章节顺序必须逐项对齐招标文件的文件组成清单**（含条目内顺序，如"应急(6)在复盘(7)前"）。开工先把清单抄成 checklist。
- 商务部分只做四类章：企业简介与资质 / 团队配置 / 案例证明（真截图）/ 服务承诺。**不做「投标响应总表」「资格一票否决对照表」「组成索引」这类应答表**——纸质盖章件里才需要，演示文件里是标书腔。
- 技术清单里缺位的项（如"平台合规适配""售后履约配套"）各给一个三卡精简章补位，不做大表。

## 2. 条款对照框（.tender）的度

- 保留：每个技术章开头一个金边框，引条款号+要求要点+一句响应。
- 删除：封面编制说明、项目编号/招标人/投标有效期字段、"盖章另附""佐证四件套成册"括注、合规响应矩阵大表、评分表引用式的响应（"对应评分 I 项五条"→ 直接写内容）。

## 3. 数字与内容红线

- 预算比例取招标区间**下限**，两档同比例（甲方会质疑"为什么排上限"）。
- 美国项目的数据条只放美国纪录（日本战绩进案例章，可都写、不能只写日本）。
- 报价定式：**基础服务费 + 比例佣金**两张卡，不按双目标分列金额，无模式 B/报价说明/结算卡（参考值：$12,000 + 9% 页面最终金额）。
- 团队人数列直接写配置数，不写"要求/配置"两截式。
- 工具不具名（Klaviyo→EDM 工具）、Newsletter 删、社媒只留 Facebook、ROAS 写整数区间（2–3）、"违约金"字样删、InDemand 免费运维不主动承诺（商务决策，先问 Evan）。
- 叙事禁区：求婚/订婚/婚嫁导向（上众筹的产品用「设计×科技」框架）、医疗声明、"全球首创"。

## 4. 交付物族

同一套内容四种产物：①滚动网站（主交付，Vercel `vercel deploy --prod --yes`，干净目录只放 index.html）②打印 PPT（print_build 管线：16:9 slide 分页→playwright @2x 截图→python-pptx 整页图，本 skill 默认不做，用户要时参考莎士比亚案 scratchpad/build/print_build.py 思路重建）③逐页讲稿 docx（见 speech-guide.md）④盖章件清单（提醒用户线下补：投标函/营业执照/信用报告/简历+背调授权/案例佐证册/无违规承诺书，模板缺失的向招标联系人索取）。

## 5. 工程定式

- build.py 用 ORDER 数组做 section 重排，章节顺序调整不动源文件。
- 模块加 id（g-*），打印版和图谱都按 id 抽取。
- 图例类组件严格用母版内部结构（.pieleg 必须 .ln/.pv 包裹，裸文本会竖排）。
- 改任何档位/金额后全文搜旧数；QA 跑 proposal-site 的清单 + 禁词扫描。

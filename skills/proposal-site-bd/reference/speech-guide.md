# 逐页讲稿 · 口径规则（源自用户 2026-08 对莎士比亚讲稿的逐句修改）

> 交付形态：docx（Microsoft YaHei，A4，页码），每页一段，段落 100–250 字，页码标题与 PPT 一一对应。
> 参考样本：`speech-sample.txt`（用户改定版全文，动笔前先读一遍找语感）。

## 七条硬规则（每条都是用户亲手删/改出来的）

1. **只陈述，不导演。** 删一切舞台指令与喊话：「这一页值得多停十秒」「请重点看」「收个尾」「放这一页想说明的是」「欢迎评审随便抽一行验算」「不用听我们说,现在打开 KS 搜」——统统不要。信息直接讲，评审自己会看。
2. **对甲方全程协作口径，不下通牒。** 禁用「必须/锁死/决策闸/前提有三个/否则顺延」。定价、页面这类事写成弹性流程：「品牌方给出价格后，我们会通过问卷等形式测算，通常讨论好几轮，直到上线」「页面框架出来之前还会有一轮甚至几轮的修改和确认」。保底机制说「我们先写了一版」而非「我们主动给」；纠偏说「调优方案」而非「诊断和纠偏」。删「Leads 不达标就延后上线」这类前置门威胁。
3. **不口播内部机制与硬承诺。** 档位控量逻辑（"Secret 控量不挤压主力"）、渠道分工逻辑（"Meta 找人 Google 接搜索"）、主体架构（北京/香港）、背调承诺、"写进合同"、数据存储承诺细节——都留在文件里，口头不展开；合规类的说到「也是我们会关注到的一点」即止。
4. **数字不说死。** 总数用「截至目前」带过不报数；能力类数字报底数+以上；InDemand 续销 +10-15% 这类未承诺收益预测整句删。
5. **不替甲方做选择。** 三套视觉不说"我们建议 B 起步"，只呈现选项；订金档不说"主推 $10"，说两档都会通过测试调整。
6. **不贬不比。** 删「珠宝老手、众筹新手的组合」这类给甲方贴标签的话；删「拿下他等于拿下可信度」这类自夸修辞；结尾不加「省的是时间降的是风险」「我们的计划不会停在筹款结束那一天」式的金句尾巴。
7. **用词习惯**：意向「高」不说「纯」；转化「相对也会更高」不说「稳」；竞品差距说「无法与本品进行比较」不说「跟不了」。

## 生成流程

1. 按最终版 PPT 页序列出每页标题与关键数字（数字必须与页面完全一致，出稿前逐页核）。
2. 每页一段：第一句接上页的自然过渡，中间讲这页的事实与数字，结尾不留修辞尾巴。
3. 写完过一遍七条规则 + chinese-business-copy 的禁词表（不是…而是…、口语词）。
4. docx 生成脚本参考莎士比亚案 speech.js（NODE_PATH 指向 npm root -g 后 node 执行）。

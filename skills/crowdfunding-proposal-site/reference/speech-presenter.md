# 演讲稿 + 演讲者窗口

> 来源：2026-11 Cephalon Lucy 方案上会。用户原话："按照网页念会很无聊"；第一版被打回"太啰嗦、太随意、不是和大陆人沟通的句式"；定稿口吻见下。
> 活代码：`templates/immersive-bay/presenter.html` + `assets/js/notes.js` + app.js「presenter sync」段；`tools/notes2md.py` 从 notes.js 生成可打印的 `演讲稿.md`。

## 1. 什么时候做
方案要在会上讲（"会上展示/要讲/路演/共享屏幕"）就做。一屏一段，跟网页章节一一对应；只有一个数据源 `notes.js`。

## 2. 口吻（定稿）
**简洁、带一点谦虚、大陆商务沟通句式。** 品牌方比我们更懂产品，所以前半段（产品、卖点、配置）点到为止。

- 每段 1–3 句，全长 10–15 分钟（31 屏 ≈ 12 分钟）。数字只说关键的，细节交给网页和提词。
- 章节过渡一句话：「第一章是我们的初步判断以及受众场景。」「第二章是市场与竞争。」
- 产品段先让一步：「产品价值这部分各位比我们更熟悉，我这边简单过一下我们的理解。」
- 常用措辞：我们这边、暂定、初步、我们根据现有的产品资料、压在（上线时间压在…）、需要品牌方重点配合、大家可以会后再细看、当然这个比例可以根据实际情况做调整。
- 收尾：「以上就是我们这次方案的全部内容。我们这边理解不到位的地方，也欢迎大家指正，谢谢。」
- 禁：口语化随意词（"扛""底气""加一把火""成败基本看""我挑重点讲"）、排比三连、"值得注意的是"、"不是…而是…"、破折号、对品牌方下判断（"这几项数据拿到手会是很硬的素材"）。
- 不讲网页的交互说明（"点对应的盘位就能过去"——删）。

## 3. notes.js 结构
```js
export const NOTES = [
 { "sel": "#hero",  "ch": "开场", "t": "开场", "sec": 40, "s": "第一段\n第二段", "cues": ["2027.01.21 上线", "预热 45 天"] },
 { "sel": "stmt:0", ... },              // 第 n 个 [data-stmt] 全屏主张
 { "sel": "[data-n=\"04.B\"]", ... }    // 任意 CSS 选择器；顺序必须与页面从上到下一致
];
```
`sel` 指向该屏的锚元素；场景型锚点（hero/spin/unbox/drive/outro）跳转时落在场景内合适的 p（0 / .14 / .62 / .64 / .72）。

## 4. 演讲者窗口（presenter.html）
- 方案页按 **P** 打开（`window.open('presenter.html','lucy-presenter')`）；同源两个窗口用 `BroadcastChannel('lucy-presenter')` 同步。
- 方案页每 400ms 广播当前屏 `{type:'pos',idx}`（视口 55% 线以上的最后一个锚点）；收到 `{type:'goto',idx}` 就平滑滚过去。
- 演讲者窗口：当前屏讲稿（大字、可 A+/A−）、提词胶囊、下一屏预告、计时器（点开始/暂停、双击归零，超时变橙）、时钟、连接灯；←/→/空格/PgUp/PgDn（翻页笔）翻页；F 切换跟随。
- **防回弹**：翻页后两端都锁 2.6s（方案页 `noteHold`、演讲者 `hold`），否则方案页滚动途中广播旧位置会把讲稿拽回去。
- 方案窗口不可见（`document.hidden`）时跳转用 immediate，不做动画。
- `presenter.html` 加 `noindex`；网页上不放入口。它在线上可被知道 URL 的人打开——交付时告诉用户。

## 5. 开会共享屏幕（给用户的说明，交付时照抄）
1. 打开方案页 → 按 P 打开演讲者窗口。
2. 会议软件（腾讯会议/飞书/Zoom/Teams）选 **共享窗口**，选方案页那个浏览器窗口，**不要选共享整个屏幕**。演讲者窗口是另一个窗口，对方看不到。
3. 有外接屏：方案窗口放共享的那块，演讲者窗口拖到另一块。只有一块屏：演讲者窗口缩小放侧边/下方，别把方案窗口完全盖住（被完全遮挡时浏览器可能暂停动画）。
4. 会前在会议软件里预演一次共享，确认对方看不到讲稿。

# 细分内容导航

长方案按会议跳读设计。正文模块是导航数据源，不增加无对应内容的入口，也不改变原有沉浸式场景。

## 母版实现

- `index.html`：实际内容容器或标题写 `<div id="budget" data-nav="预算测算">…</div>`。ID 唯一稳定；标签用客户熟悉的模块名，不写硬盘/部件名。
- `assets/js/quick-nav.js`：按 DOM 阅读顺序生成固定顶栏、目录细分项与上一项/下一项；滚动更新高亮。新增或移除模块不需要维护第二份导航数组。
- `assets/js/app.js`：`initQuickNav({ goTo, closeMenu })` 在导航初始化后调用；加载结束 `quickNav.restore()` 恢复 hash。细分跳转使用 immediate 模式，跳过长距离滚动与开盖动效；大章节仍保留动效入口。
- `assets/css/site.css`：顶栏高度由 ResizeObserver 写入 `--header-height`；所有锚点按实际高度避让。宽屏细分按钮可换行，窄屏横滑；手机目录仍展示所有细分入口，不得整排隐藏。

## 每份方案应覆盖的入口

根据实际内容设置：核心判断、受众场景、市场竞品、定价档位、预算测算、页面叙事、订单来源、KOL与广告、广告素材、执行时间线、可行性、相关案例、KOL实绩、线下资源、平台资源。用户删掉某模块时也删对应入口，不为凑按钮数量新增业务内容。

预算入口对准章标题；订单来源对准饼图标题；素材对准素材条上方标题；平台资源单独设锚点，不能全都只跳案例章。

## 迁移与检验

复制 quick-nav.js、CSS 尾部导航样式、`#quickNav` 和 `#menuTopics` 容器及 app.js 初始化/恢复调用；保留原有模型、色块、预算切换与演讲者同步。所有主要入口应有可读标签、键盘焦点和当前项 aria-current。hash 链接可复制、刷新、返回；按键处理避免干扰输入控件。

使用 ego-browser 验证桌面 1440/1600 与手机 375/390 CSS 像素：逐项点击后目标标题位于顶栏下方；检查上一项/下一项、首尾禁用、完整目录、浏览器返回、深链接刷新、手机横滑、页面无横向溢出。截图前等待字体、模型和滚动布局稳定。模板验证只验证本次改动，不能据此声称新产品数据也已核实。

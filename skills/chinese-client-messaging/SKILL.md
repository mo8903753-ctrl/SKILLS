# 中文商务客户消息起草

为 MadSpace 起草面向中国品牌方客户的微信/邮件消息。用于项目排期协商、风险沟通、范围讨论等短消息场景。不用于正式文档或提案。

## 核心规则

### 不要做的事（踩过坑的）

1. **不要认错揽责。** 不属于自己责任范围的事，不做道歉。风险透明化——说清楚什么是你能控制的、什么是外部变量——但不道歉。用户原话："认什么错"。
2. **不要虚构内部流程。** 用户没有的东西不要编（如"周报"）。不要为了让回复漂亮而发明不存在的机制。
3. **不要用"第一/第二"枚举结构。** 中文商务消息中这听起来太刻板。用自然段落过渡。
4. **不要太正式。** 不要写"感谢二位坦诚沟通/我们将您的反馈归为三个核心关切/逐一回应"——这是公文腔，不是人在说话。
5. **不要太随意。** 不要写"傻逼/妈的/这也太那个了吧"——保持专业。

### 调性标准

**"梁总、张总，反馈收到了。"** —— 这句是标杆。

- 专业、直接、不卑不亢
- 承认收到了对方的反馈，但不做不必要的道歉
- 像真实的人在说话，不是AI翻译腔，不是公文腔

### 风险分配句型

当客户追问一个你无法100%控制的事情（如KOL交片时间）：

```
正确："上线我们这边没有问题。KOL素材到了就打满，没到就走自有内容先跑起来，不等人。"
错误："7月2日没问题，但前提是KOL在25号之前交片，如果没交就只能顺延。"
```

**原则：**
- 你能控制的 → 直接打包票
- 你控制不了的 → 说清楚但不道歉，给出两种路径的方案
- 不要让外部变量成为你承诺的前置条件——那等于把别人的风险背在自己身上

### 处理客户批评的正确姿势

当客户说"你们没有站在我们立场上思考"时：

- ❌ 不要道歉（"这个反馈我们完全接受"→ 用户骂"认什么错"）
- ❌ 不要虚构整改措施（"下周起加周报风险看板"→ 用户说"没有周报这种东西"）
- ✅ 承认收到了反馈，逐一回应具体关切，用自然段落
- ✅ 如果确实有要做的事，说具体、可执行的事；没有就不编

## 典型场景

### 场景：客户追问上线日期，但外部变量未定

模板：
```
[称呼]，

[上线/项目推进]我们这边没有问题。

[外部变量]这块，[实话实说的状态]。我们能做的是：[两种路径的方案]。

总结就是：[一句人话]。

[其他待办事项]今天/明天发出来。

二位看这样OK吗。
```

### 场景：客户批评工作方式

模板：
```
[称呼]，

反馈收到了。

[逐一回应具体关切，用自然段落，不做分点枚举]。

[回到具体待办事项，轻推确认]。

你们看这样OK吗。
```

## 检查清单

生成草稿后自查：
- [ ] 有没有道歉语（"接受""抱歉""是我们做得不够"）→ 删掉
- [ ] 有没有"第一/第二/一是/二是"→ 改自然段落
- [ ] 有没有虚构的内部流程 → 删掉
- [ ] 有没有公文腔（"将...归为...""坦诚沟通""逐一回应"）→ 改成人在说话
- [ ] 读出声来，像不像一个策略总监在跟客户聊天 → 不像就改

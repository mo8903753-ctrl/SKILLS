# 众筹预热投广前测报告生成器（增强版）

## 概述

本 skill 用于生成众筹产品（Kickstarter / Indiegogo）的预热期投广前测报告。报告包含 Meta 广告数据分析、素材成效分析、问卷调查结果、投广洞察和后续众筹推进方案，最终输出美化的 HTML 文件（含 Chart.js 可视化图表）和 PDF 文件。

## 工作流程

### 第一步：主动收集信息

当用户触发此 skill 后，按以下顺序向用户收集所有必需信息。不要一次性罗列所有需求，而是分批询问，每批尽量控制在 2-4 个问题，根据用户回答推进。

**第一批 - 基础信息：**
1. 产品名称（如 Guimeet Go 5）
2. 前测日期范围（如 10 月 31 日 - 11 月 5 日）
3. 众筹目标金额（如 $500,000）
4. 产品平均单价（如 $230）

**第二批 - 广告数据：**
请用户上传以下 Meta 广告后台导出的表格（CSV 或 Excel）：

1. **广告系列级别汇总表**
   - 用途：汇总整体 Campaign / Ad Set 表现，解析兴趣分组、地区、目标、性别
   - 必需字段：Campaign name、Ad set name（如有）、Amount spent、Results、Cost per result、Impressions、CPM、Link clicks、Cost per link click、Link CTR

2. **按日期分组的日报表**
   - 用途：生成“每日数据拆解”板块
   - 分组维度要求：Date
   - 必需字段：Date、Amount spent、Results、Cost per result、Impressions、Link clicks、Link CTR

3. **人口统计 breakdown 表**
   - 用途：生成国家 / 年龄 / 性别分析
   - 分组维度要求：Country、Age、Gender
   - 必需字段：Amount spent、Results、Cost per result

4. **版位 breakdown 表**
   - 用途：生成 Facebook / Instagram / Messenger 等版位分析
   - 分组维度要求：Placement / Publisher platform / Platform position
   - 必需字段：Amount spent、Results、Cost per result

5. **素材级数据表（Ad / Creative 维度）**
   - 用途：生成“投广素材成效”板块
   - 分组维度要求：Ad name 或 Ad creative / Image / Video thumbnail
   - 必需字段：Ad name、Amount spent、Results、Cost per result、Impressions、Link clicks、CTR
   - 如后台无法直接导出素材缩略图，至少需要 Ad name 与素材文件一一对应

如果用户提供的表格缺少某些维度：
- 缺少按日期日报表：报告第一板块降级为“区间整体数据拆解”，并明确标注“未提供日级数据”
- 缺少素材级数据：报告第二板块不生成素材对比，只保留“暂未提供素材级转化数据”的说明
- 缺少人口统计或版位 breakdown：对应子板块跳过，并在报告中说明原因
- 缺少关键字段（花费、Results、点击、展示）：必须先向用户补要，不能直接猜测

**第三批 - 问卷和素材：**
1. Google Forms 问卷结果的长截图（直接发图片即可）
2. 素材原图或视频封面图（按素材级数据表中的 Ad name 顺序提供）
3. 如果素材文件名与广告后台 Ad name 不一致，要求用户提供 `Ad name ↔ 素材文件名` 对照表

### 第二步：解析 Meta 广告数据

#### 2.1 解析广告系列名称

广告系列名称使用全角分隔符 `｜` 分隔，格式通常为：`地区｜目标｜兴趣｜性别`

示例：
- `北美｜lead｜tech｜男` -> 地区 = 北美, 目标 = lead, 兴趣 = tech, 性别 = 男
- `欧洲｜lead｜Photography ｜男` -> 地区 = 欧洲, 目标 = lead, 兴趣 = Photography, 性别 = 男
- `欧美｜上线后｜RT ｜男` -> 地区 = 欧美, 目标 = 上线后, 兴趣 = RT, 性别 = 男

**重要**：前测报告只分析预热期（lead 收集）的广告系列，即目标为 `lead` 的 campaign。`上线后` 等其他类型不纳入前测报告的第一板块分析。

#### 2.2 提取关键指标

从表格中提取以下字段（列名可能是中文或英文，需要灵活匹配）：

| 报告指标 | 对应表格字段 |
|---------|-----------|
| 花费 | 已花费金额 (USD) / Amount spent (USD) |
| Leads 数 | 成效 / Results（当成效指标为 lead 时） |
| CPL | 单次成效费用 / Cost per result |
| 展示次数 | 展示次数 / Impressions |
| CPM | 千次展示费用 (USD) / CPM |
| 点击量 | 链接点击量 / Link clicks |
| CPC | 单次链接点击费用 (USD) / Cost per link click |
| CTR | 链接点击率 / Link CTR |
| CVR | 计算得出：Leads 数 / 点击量 |

#### 2.3 数据汇总计算

**总览数据：**
- 总花费 = 所有 lead campaign 的花费之和
- 总 Leads = 所有 lead campaign 的成效之和
- 整体 CPL = 总花费 / 总 Leads
- 整体 CPM = 总花费 / 总展示次数 × 1000
- 整体 CTR = 总点击量 / 总展示次数 × 100%
- 整体 CPC = 总花费 / 总点击量
- 整体 CVR = 总 Leads / 总点击量 × 100%

**每日数据拆解：**
- 按 Date 汇总每天的花费、Leads、CPL、CTR、CPC、CVR
- 如果没有日级报表，则此板块降级为日期范围内的整体汇总说明

**兴趣分组数据：**
按解析出的广告系列名称分组，每组计算花费、Leads、CPL。同一兴趣分组下，如果有多个子兴趣词（即 ad set 级别数据），也要列出每个子兴趣词的明细。

**人口统计数据（来自 breakdown 表）：**
- 按国家：每个国家的花费、Leads、CPL
- 按年龄段：25-34、35-44、45-54、55-64、65+ 的花费、Leads、CPL
- 按性别：男 / 女的花费、Leads、CPL

**版位数据（来自 breakdown 表）：**
- Facebook、Instagram、Messenger 等各版位的花费、Leads、CPL

### 第三步：Benchmark 对比

使用以下固定 Benchmark 值进行对比：

| 指标 | 预热期 Benchmark |
|------|---------------|
| CPM | $18-$20 |
| CTR | 2%-3% |
| CPC | $0.8-$1 |
| CPL | $3-$5 |
| CVR | 15%-20% |

在表格中，用颜色标注当前数据与 Benchmark 的关系：
- **绿色**：优于 Benchmark 范围
- **红色**：差于 Benchmark 范围
- **蓝色**：在 Benchmark 范围内（也可用于当前数据展示）

### 第四步：投广素材成效分析

**投广素材成效板块生成规则：**
- 按 Results 从高到低排序，展示转化最高的素材
- 同时列出 CPL 高、无转化、或点击高但不转化的素材作为“待优化素材”
- 每个素材至少展示：图片、花费、Leads、CPL、CTR
- 若用户只提供数据未提供素材图片，则保留数据卡片，不展示图片
- 若用户未提供素材级数据，则用提示文案说明该板块未生成

### 第五步：解析问卷截图

用户会发送 Google Forms 问卷的长截图。读取截图中的所有问题和数据，通常为 15 题，但以用户实际提供内容为准。

**问卷题目结构（内容会因产品而异，但框架通常如下）：**

1. 用户的主要顾虑是什么？（多选 - 水平柱状图）
2. 哪项产品特点吸引你参与？（多选 - 水平柱状图）
3. 各功能重要性评分（1-5 分 - 每个功能一个柱状图）- 包含多个子功能
4. 购买时关注哪些方面？（多选 - 水平柱状图）
5. 价格过低会怀疑质量的价位？（饼图）
6. 合适的价格？（饼图）
7. 有点贵但可接受的价格？（饼图）
8. 太贵的价格？（饼图）
9. 特定价格下的支持意愿？（1-5 分评分 - 柱状图）
10. 是否参加过众筹？（饼图）
11. 性别（饼图）
12. 年龄（饼图）
13. 地区 / 国家（饼图）
14. 职业（饼图）
15. 开放反馈（文字列表）

**对每个问题：**
- 用 Chart.js 生成对应图表（保持与原报告一致的图表类型）
- 自动生成中文总结，格式为 `第一：xxx / xxx`，提取占比最高的选项

**问卷截图异常处理规则：**
- 若截图题数不是 15 题，以用户实际提供内容为准，不强制补足
- 若某题截图不完整、文字被裁切、比例看不清，必须向用户补要更清晰截图
- 若开放题（Q15）内容过长，只提炼高频反馈关键词和代表性原话，不全文照搬
- 若同一问题包含多个子题（如功能评分），将其拆成多个独立图表或一个分组柱状图，优先保证可读性

### 第六步：撰写前测期投广洞察

根据第二步、第四步和第五步的数据分析，自动撰写洞察要点（5-7 条），保持以下风格和维度：

1. **整体表现评估**：当前指标与 Benchmark 对比，哪些高哪些低
2. **受众性别**：目前投放主要是哪个性别群体，后续策略建议
3. **年龄分布**：哪些年龄段转化较多，哪些效果稳定
4. **地区 / 市场分析**：哪个市场是主力来源，CPL 表现如何，建议重点优化哪个市场
5. **平台版位分析**：Facebook 与 Instagram 的对比，花费占比和性价比
6. **受众 / 兴趣分组建议**：哪些受众模型表现最优，建议增加预算
7. **素材策略建议**：哪些创意角度适合放量，哪些素材需要停投或重做

洞察用 bullet point 格式，每条洞察以分析为主，末尾附带简短的策略建议。

### 第七步：生成后续推进方案（第五板块）

这一板块大部分是固定模板，只有花费预估表和邮箱计算需要根据变量调整。

#### 7.1 固定不变的内容（直接复用模板）

以下内容完全不需要修改，直接从参考文件 `references/fixed_templates.md` 中加载：

- **后续策略**文字（5 条要点）
- **KS 各流量订单来源预估**（饼图 + 说明）
- **各付费渠道投产比预估**（柱状图 + ROI / ROAS 数据）
- **KOL 合作策划**（工作安排 5 步）- 注意：KOL 垂直领域需根据产品类型调整，粉丝量 / 合作形式 / 计划数量不变
- **众筹社区策划**（社群对比表格，只列社群名 + 套餐价格，不要平台 / 用户数 / 推广方式 / 预期转化。套餐 1 列标题只写“套餐 1”，不要写“不建议”）
- **风险评估**（5 条固定风险 + 应对策略）
- **结尾**（固定感谢语）

#### 7.2 需要按比例计算的内容

**各付费渠道后续花费预估表：**

营销费用总计 = 众筹目标 × 17.2%

各渠道分配比例（固定比例）：

| 渠道 | 占营销总费用比例 |
|------|--------------|
| 预热广告（预热 30 天） | 25.58% |
| 上线广告（上线 45-60 天） | 58.14% |
| KOL 合作 | 5.81% |
| 众筹社群营销 | 9.30% |
| 其他营销工具 | 0.58% |
| 抽奖奖品 | 0.58% |

**预热邮箱数量计算：**

使用用户提供的众筹目标和平均单价：
1. 总订单数 = 众筹目标 ÷ 平均单价
2. 前三天订单 = 总订单数 × 20%
3. 前三天来自预热邮箱的订单 = 前三天订单 × 20%
4. 预热 leads 转化率 = 2%（固定）
5. 需要收集的邮箱数 = 前三天来自邮箱的订单 ÷ 2%
6. 预热花费 = 邮箱数 × 当前 CPL（从数据计算得出）
7. 预热花费占总金额比例 = 预热花费 ÷ 众筹目标

### 第八步：生成 HTML 报告

使用 `scripts/generate_report.py` 生成最终的 HTML 文件。

**HTML 报告要求：**

- **整体风格**：专业、简洁的报告风格，白色背景，使用蓝色和紫色作为主色调
- **图表库**：使用 Chart.js（通过 CDN 引入）
- **图表配色**：
  - 柱状图：浅蓝色（#87CEEB）表示花费、紫色（#7B68EE）表示 Leads、青绿色（#40E0D0）表示 CPL
  - 饼图：使用紫色系列配色
  - 水平柱状图（问卷）：紫色（#6B4C9A）
- **表格样式**：带边框的简洁表格，表头浅灰色背景
- **字体**：中文使用系统默认字体，英文使用 sans-serif
- **页面宽度**：最大 900px 居中
- **板块结构**：每个大板块用 `<h2>` 标题，板块间有明显间距
- **图表尺寸**：柱状图宽度 100%、高度 300-400px；饼图宽度 300px 居中

**固定图表资源：**
- **KS 各流量订单来源预估**：使用 Chart.js 饼图 + 深色背景容器（#1a1a2e），左侧饼图，右侧各渠道说明文字（参考 `references/fixed_charts_data.md` 中的颜色和数据）。数据比例固定不变。
- **各付费转化渠道投产比预估**：使用 Chart.js 双系列柱状图（蓝色 = 花费预算，金色 = 转化金额），下方标注 ROI / ROAS 彩色标签。金额根据众筹目标按比例调整，ROI / ROAS 比值固定。

### 第九步：生成 PDF

使用 Python 将 HTML 转换为 PDF，按以下顺序检查可用依赖：

1. 优先使用 `playwright`
2. 若 `playwright` 不可用，则尝试 `weasyprint`
3. 若 `weasyprint` 不可用，则尝试 `pdfkit` + `wkhtmltopdf`
4. 若以上方案都不可用，至少交付 HTML，并明确告知用户当前环境缺少 PDF 生成依赖

### 第十步：输出和交付

**输出目录规则：**
- 若用户明确指定输出目录，则保存到该目录
- 若用户未指定，则默认保存到当前工作目录下的 `output/` 文件夹
- 若 `output/` 不存在，则自动创建

**输出文件命名规则：**
- HTML：`[产品名称]_pretest_report.html`
- PDF：`[产品名称]_pretest_report.pdf`

**交付要求：**
- 返回 HTML 和 PDF 的实际保存路径
- 简要说明哪些板块因原始数据缺失而被跳过或降级

## 报告完整板块结构

```text
[产品名称]预热投广前测报告

一、每日数据拆解([日期范围])
  ├── 总花费 / Leads 数量 / CPL 概览
  ├── 关键数据 VS Benchmark 表格
  ├── 名词解释（CPM / CTR / CPC / CVR / CPL）
  ├── 每日趋势拆解（若有日级数据）
  ├── 兴趣成效（分组柱状图 + 明细列表）
  ├── 国家（柱状图 + 文字）
  ├── 年龄（柱状图 + 文字 + 简评）
  ├── 性别（柱状图 + 文字）
  └── 广告版位（柱状图 + 文字）

二、投广素材成效
  ├── 转化比较多的投广素材（图片 + 数据）
  └── 成效较差和暂无转化的广告素材（图片 + 数据）

三、前测期投广洞察
  └── 5-7 条 bullet point 洞察

四、问卷调查结果
  ├── Q1-Q4: 多选题（水平柱状图 + 中文总结）
  ├── Q5-Q8: Van Westendorp 价格题（饼图 + 中文总结）
  ├── Q3 子题 & Q9: 评分题（柱状图 + 平均分）
  ├── Q10-Q14: 人口统计（饼图 + 中文总结）
  └── Q15: 开放反馈（文字列表）

五、后续继续推进众筹方案 - 以 [众筹目标] 为众筹目标
  ├── 后续策略（固定模板）
  ├── KS 各流量订单来源预估（固定图表）
  ├── 各付费渠道后续花费预估（按比例计算的表格）
  ├── 各付费转化渠道投产比预估（固定图表）
  ├── 预热邮箱数量计算（公式计算）
  ├── KOL 合作策划（垂直领域根据产品调整，其余固定）
  ├── 众筹社区策划（固定表格，只列社群 + 套餐价格）

六、风险评估（固定模板，5 条风险 + 应对策略）

七、结尾（固定感谢语）
```

## 参考文件

- `references/fixed_templates.md` - 所有固定模板内容（后续策略、KOL 策划、社区表格等）
- `references/fixed_charts_data.md` - 固定图表的数据（流量来源预估、投产比数据）
- `references/benchmark_values.md` - Benchmark 基准值
- `scripts/generate_report.py` - HTML / PDF 报告生成脚本（必须存在；若不存在需先创建）

## 脚本职责说明

`scripts/generate_report.py` 需要完成以下工作：
- 读取并清洗 Meta CSV / Excel 数据
- 自动匹配中英文列名
- 过滤指定日期范围内的 lead 类型 campaign
- 计算总览指标、Benchmark 对比、兴趣分组、国家 / 年龄 / 性别 / 版位结果
- 生成素材成效板块数据
- 解析问卷截图后的结构化结果并渲染图表
- 拼装固定模板板块
- 输出最终 HTML
- 在依赖可用时导出 PDF

## 注意事项

- 所有金额保留两位小数，百分比保留两位小数
- 图表中的数据标签要清晰可读
- 中文和英文之间加空格以提高可读性
- 问卷部分的图表标题使用英文原文（与 Google Forms 保持一致），总结使用中文
- 如果 Meta 表格中某些数据缺失或列名不匹配，主动向用户确认
- 前测报告只分析用户指定日期范围内的 lead 类型 campaign 数据
- 若缺少某块数据，则必须在报告对应位置写明“该板块因原始数据缺失未生成”，而不是静默删除
